### C-46. 候補者プロフィールは現在値と追記履歴を同時に保存する

候補者の記録項目は、氏名、かな、生年月日、学校、学部、メール、電話、LINE、
紹介者、担当者メモ、顔写真をヘッドハンティング画面から編集できる。顔写真は
JPEG / PNG / WebP、2MB以下とし、MVPではdata URLとして保存する。規模拡大時は
オブジェクトストレージへ移す。

`persons` の現在値を更新すると同時に `person_profile_revisions` へ全項目の
スナップショットを追記する。履歴は更新・削除禁止。アプローチ状態は既存の
追記型 `approach_events` に担当者付きで記録する。評価、理由、合否判断は応募の
選考記録から編集し、集計値や推定値は事実から導出するため直接編集させない。

### C-46. `setPersonApproachState` が必ず例外で落ちていた

実行⑨。**アプローチ状態の編集は、画面からもテストからも一度も成功していなかった。**

```js
[...].every(UUID.test)      // ← this を失って TypeError
```

`UUID.test` をメソッドのまま渡していたため、`this` が `undefined` になり
「incompatible receiver」で必ず落ちる。**入力を検証するつもりの行が、
検証ではなく事故そのものになっていた。**

同時に、この経路を守るはずの `tests/29_profile_editing.test.ts` も
落ちていた ―― マイグレーション 0016 が使う `sort_order = 10` と

- 検証は `(v) => UUID.test(v)` に直した
- テストは既存の並び順とぶつからない `sort_order = 15` に直した
