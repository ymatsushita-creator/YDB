### C-142. 押した直後の骨組みを入れた（C の実装）―― **枠と見出しだけ**にした

依頼者の指示（実行⑮）――「進んでいることを見せる」。骨組みの形は委ねられた
（「帯だけ薄く光る」か「枠だけの灰色のカード」か）。**選んだのは前者ではない。**
理由は好みではなく、2つの制約である。

#### ① 「前の画面のまま帯だけ光る」は `loading.tsx` では作れない

`loading.tsx` は**押した瞬間に前の画面を骨組みへ置き換える。**
前の画面を残したまま「動いている」と伝えるには遷移状態をクライアントで見ることになり、
**`'use client'` が3つ目になる**（C-95 / C-104。表と追従光の2つだけ）。
**規律のほうを優先した。**

#### ② 灰色のカードは「まだ無いもの」を「ある」ように見せる

この製品は 0017 から**「無いことを 0 と書かない」「算出なしと書く」**を守ってきた
（C-127 でもホームの確度で同じ線を引いた）。数字の位置に箱を並べるのは、
その線を骨組みだけ例外にすることである。**出すのは器の寸法と、読み込み中だという事実だけ。**

```
app/loading.tsx   操作柱の位置（--logo-w の列）・横バーの位置（--logo-h の厚み）・
                  「読み込み中」の1行。role="status" で読み上げにも渡す
                  ★ 箱を並べない・数字を出さない・動かさない
```

★ 器の寸法は `Shell` と**同じトークン**で描く（`hh-frame` / `hh-main` をそのまま使う）。
数値を書き写すと器の寸法が2箇所になり、必ずどちらかが古くなる。

#### ★ 再現して撮るまで、柱が消えたまま出していた

面の色を持っているのは `.hh-sidebar` で、`.sidebar-region` は角丸と余白だけだった。
骨組みに `.hh-sidebar` は付かないので、**左の柱が透けて器が崩れて見えていた。**
帯は認証の内側なので、**同じ CSS で骨組みだけを再現した頁を作って撮った**
―― それで気づいた。`background: var(--bar-face)` を敷いて直した。

★ **見ていないものを見たと書かない。** 目で見たのは再現した頁であって、実データの画面ではない。

#### これが出る場面は多くない

C-141 で30秒の控えを入れたので、一度開いたタブへ戻るときは往復そのものが起きない。
骨組みが出るのは**初回・30秒経過後・期を切り替えたとき**である。
体感の本丸は D（本番を実DBへ向ける）で、そちらは**実データを出すという判断**であって
こちらの判断ではない（C-84 / C-94）。
