### A-15. デモの出来事が、指定した日の1日前に起きていた

A-14 の確認で登場人物の画面を開いたら、`persons.note` に「2026-05-18 に
識別された」と書いたつもりの人が **2026/05/17** と表示されていた。

`src/seed/demo.ts` の `at()`。

```ts
const d = new Date(`${base}T00:00:00+09:00`)  // その瞬間の UTC 日付は前日
d.setUTCHours(hour - 9, minute, 0, 0)          // 前日のまま時刻だけ入る
```

JST 深夜を基準に取ると、その瞬間の UTC 日付は前日である。
そこへ `setUTCHours` で時刻を入れるので、**どの時刻を渡しても指定日の
1日前**になっていた。A-1（`::date` が接続のタイムゾーンに依存する）と
同じ間違いを、集計ではなくデータの生成側でやっていた。

**表に出なかった理由が重要である。** 応募は
`at(plan.applicationOpen, day, ...)` から作るので、`day = 0` の応募は
応募開始日の前日に発生していた。ところが `f_funnel_daily` は応募開始日
より前の出来事を初日に寄せる（0004 の `clamped`）。**丸め込みが辻褄を
合わせてしまい、集計値としては正しく見えていた。**
実行②の「表示の丸めで注記が画面上の嘘になった」と同じ形である。

**対応**: 暦日の足し算は UTC 深夜を基準に行い、`YYYY-MM-DD` を返す。
時刻はタイムゾーンつきのリテラルを組み立てて与え、暦の解釈を `Date` に
任せない。`partner_reaches.reach_date` の組み立ても同じ理由で直した。

直した副作用として、**年度のどの期間にも入らない接点が0件になった。**
あの形は、このずれが偶然に作っていたものだった。年度の切れ目に届く連絡は
実データでは必ずあるので、登場人物に1件を明示的に置き直した（C-15）。
**デモの経路が「バグによって偶然踏まれていた」形で、バグを直すと
検証したい経路まで一緒に消える。**

→ `tests/13_demo_coverage.test.ts`「団体経由の接点と、年度に紐づかない接点がある」
