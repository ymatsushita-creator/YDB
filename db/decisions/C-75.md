### C-75. 職員と、アプローチ状態の初期値を入れた（0024）

C-74 で人と応募は入ったが、ヘッドハンティングとボーダーラインの一覧に
1人も出なかった。これらは `v_headhunting_list`、つまり
**アプローチ状態の記録がある人**だけを出す。

記録するには `approach_events.recorded_by_staff_id`（職員）が要るが、
本番に職員が1人も居なかった。旧システムには担当者の**氏名だけ**がある。

#### メールを作らずに職員を入れた（0024）

`staffs.email` を NULL 可にした。**無いものを作らない。**
一意制約は NULL を別物として扱うので、メールの無い職員が何人居ても衝突しない。

```
職員 14 件（interview_handler / sec2_evaluator / internal_handler の氏名）
```

「ー」など担当者でない印だけの値、20文字を超える値は職員にしない。

#### 記録した人を、実在の担当者に付け替えない

誰が記録したかは旧データに無い。**取り込みが作った行だと分かる名前**を
1つ置いた ―― `旧システム取り込み`。**非活性**なので、担当を選ぶ画面には出ない。

#### 初期値は「未アプローチ」

**これは嘘ではない。** その人について、こちらは声掛けの記録を1つも持っていない。
`note` に「旧システムから移した。声掛けの記録は無い」と残してある。

★ 旧データの `status`（合格32・辞退7 など）を写していない。
それは**選考の状態**であって、アプローチの状態ではない。
段の呼び名の対応も未確認である（HANDOFF）。**運営の言葉を翻訳して記録しない。**

```
アプローチ状態 61 件（すべて「未アプローチ」・2期）
```

2期のヘッドハンティングとボーダーラインに、取り込んだ人が出ることを画面で確認。
