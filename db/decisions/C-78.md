### C-78. 関連団体をアプローチ画面へ接いだ

依頼者の指示（実行⑩）――「関連団体のところから、アプローチの画面にも接合して」。

```
関連団体   28 件（旧 youth_partnerships）
接触記録  240 件（日付つきのログ）
職員       +3 件（窓口ごとの内部担当）
```

#### ログは**2箇所**にある

旧データは同じ形のログを、団体の直下（`logs` 162件）と
窓口ごと（`partner_contacts[].logs` 256件）に持っている。
**片方だけ読むと、記録の半分以上が消える。**
同じ日・同じ内容は1件に畳んで 240 件。

内部担当も同じで、団体直下だけ見ると**窓口ごとの担当を取りこぼす**（+3人）。

#### 推定リーチは作らない

`partner_reaches.estimated_reach` は NULL のまま。
旧データに「何人に届いたか」は無い。**0 を入れると「届かなかった」という
別の事実になる。** 画面の「アプローチ可能圏（推定リーチ）」は 0 と出るが、
それは推定が無いという意味である。

#### 年度は日付から決める。近い期へ寄せない

```
接触記録 240 件 → 2期 53 件 ・ どの期にも紐づかない 187 件
```

★ **これは取り込みの失敗ではない。** 記録の日付は 2025-08-27 〜 2026-07-02 で、
2期の期間（集客開始 2026-02-01 〜 選考終了 2026-04-15）の外に大半がある。

そして**2期の集客開始日 2026-02-01 は推測値である**（`0002_season_2026`）。
実際の団体折衝は **2025-08-27 から始まっていた。**
これは推測が実測とずれていた証拠だが、日付は集計定義そのものなので
**黙って直さない。** `season_revisions` に履歴を残して直す（原則4）。
**依頼者の指示待ち。**

#### 踏んだもの

`maybeOne` で存在確認をして、2周目に「2行返った」で落ちた。
**件数で見るところを、行で見ていた。** `EXISTS` に直した。
1周目は行が無いので通る ―― **冪等は2回流さないと確かめられない。**

団体名の列が1文字ずつ折り返して**縦に潰れていた。** `nowrap` にして、
足りなければ表ごと横に送る（`.table-wrap`）。
