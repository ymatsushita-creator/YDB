### C-104. リキッドグラス ―― ボタンUIを差し替えた。**仕様書どおりにしていない箇所が3つある**

依頼者から仕様書（`liquid-glass-pc-spec.md`）を受領し、「ボタンUIはこれで直して」。
**この製品と正面から衝突する点を3つ挙げ、選んでもらった。**

```
範囲   **浮いているものだけ**（操作柱のタブ・期・帯のボタン・ポップアップ・主ボタン）
背景   **敷かない**（「色は線、面は黒」の意匠規定を守る。C-71）
追従光 **入れる**（`'use client'` をもう1つ）
```

`app/glass.css` を**4枚目の層**として足した。読む順は
トークン → 土台 → 白黒 → ブランド → ガラスで、**外せば物理ボタン（実行⑨）に戻る。**
原典（`basic/DESIGN.md`）も生成物（`app/tokens.css`）も触っていない。

#### 仕様書から外した3点（外した理由）

★ **① 単色の面の上では `backdrop-filter` を使わない。**
  操作柱と帯は真っ黒な単色（`--bar-face: #000`）で、背後に情報が無い。
  ぼかしても**何も変わらないのにコストだけ掛かる** ―― 仕様 §9 の禁止事項
  「単色背景の上での使用」そのものである。ぼかすのは背後にコンテンツがある
  ポップアップの器だけにした（実測で**同時可視1枚**。仕様 §10 の予算は3枚）。

★ **② `prefers-color-scheme` で切り替えない。**
  この製品の明暗は**OSの設定ではなく面で決まる**（操作柱は常に黒、カードは常に白）。
  OS の設定で白いカードのティントを暗色へ差し替えると、
  **黒い文字が暗い面に載って読めなくなる。** 「暗い地の上」用のトークンを別に持つ。

★ **③ 白い地の上に載るものは、ティントを別に決める。**
  仕様の既定（白の半透明）を主ボタンに当てたら、白文字が読めなくなった（下記）。

#### ★ コントラストを2回落とした（どちらも実測で見つけた）

**(1) 主ボタン。** 暗いティント `.55` を白いカードの上で使ったら、
実効の面が灰 130 になり、白文字とのコントラストが **3.83**（基準 4.5）。
白と混ざる前提で必要な濃さを計算し（実効 117 以下 ＝ 透過率 .61 以上）、
`.78` にした ―― **9.17** になった。C-73 と同じ穴である。

**(2) ポップアップの器。** 仕様 §8 は「**最も明るい背景と最も暗い背景の両方で**
AA を満たすか検証し、満たせないならティントを上げよ」と言う。
`--lg-tint-strong`（.42）で測ったら、背後が暗いとき **3.02** だった。
`.72` に上げた（実効 184 ・ 比 8.2）。**濃くしてもぼかしは見える。**

★ **私の検査器も間違っていた。** 半透明の面を測るとき「不透明な祖先の背景」を
拾っていたので、**ガラスの上の文字を測ったことになっていなかった**（0件と出た）。
半透明は**重ねて（混色して）**測る。**数えた結果を疑う前に、数え方を疑う。**

#### ★★ ビルドが、プレフィックス無しの `backdrop-filter` を消していた ★★

仕様書 §4 は `-webkit-backdrop-filter` 側から `brightness()` を落とした例を
載せている。**そのまま書いたら、Lightning CSS が2つを見比べて
プレフィックス無しのほうを消し、`-webkit-` だけを残した。**
結果、Chromium でぼかしが1枚も効いていなかった
（画面で「ぼかしを持つ要素 0 件」と出て初めて気づいた）。

**同じ値を、プレフィックス付き → 無しの順で並べる。**
`tests/46_glass.test.ts` が、2つの綴りの**値が一致していること**を見張る。
書いたのに効かない類の欠陥は、目で見て気づけない。

#### `'use client'` が2つになった

`app/_components/glass.tsx`。**ポインタの座標を CSS 変数へ書くだけ**で、
光そのものは CSS が描く（色も半径も JS に持たせない）。
リスナは**委譲で1つ**（対象は20枚を超えるので、仕様 §6 の注意に従う）。
通り過ぎた要素の変数は消す ―― 残すと次に触れたとき前の位置から光が動く。
`CLAUDE.md` の規律を「表と追従光の2つだけ」に改めた。

検証: `pnpm test`（546件）、`pnpm exec tsc --noEmit`、`pnpm build`。
デモ経路（ホーム・候補者追加・団体アプローチ・メモのポップアップ）で
切れ 0 件・**混色で測ったコントラスト不足 0 件**・ぼかし同時可視 1 枚・
ロゴと帯の一致・`corner-shape: squircle` が効いていることを確認。
追従光は「1要素だけに座標が入り、離れると消える」ことを実測した。
