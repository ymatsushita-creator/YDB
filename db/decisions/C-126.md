### C-126. フォームは表と同じ打ち方で打てていなかった ―― ★欠陥

依頼者の指示（実行⑭）――「特にフォームがスプシと同じ打ち方で打てるか」。
**打てていなかった。** 同じ文字を打って、記録が違った。

```
打った文字                        表（スプシ）          フォーム（/people/{id}/edit）
　表田　（全角空白で囲む）           表田                  **　書田　**（4文字。残る）
　a@example.test　                 a@example.test        **　form@example.test　**（19文字）
```

原因は `src/commands/profile.ts` が `btrim($)` で書いていたこと ――
**`btrim` の既定は半角空白だけ**で、全角空白（U+3000）が残る。
検査は JS の `trim()`（全角も落とす）だったので、**通ってから残った。**

★ これは 0015・C-119 で2度直した穴の3度目である。根は
**同じ集合が3箇所に書き写されていた**こと（0015 の制約・表の保存・団体のメモ）。

#### 直し方 ―― 集合の定義を1箇所にした

```
src/commands/text.ts   BLANK_CHARS（' \t\n\r　'）と blank() を置く。**定義は1つ**
profile.ts             btrim($n, $16) へ。email も同じ集合で nullif する
sheet.ts / partner.ts  自前の定義・書き写しをやめて import する
intake.ts              **照合も同じ集合にする** ―― メール／LINE／電話の
                       突き合わせが既定の btrim だと、全角空白付きで入っていた
                       古い値と当たらない（**同じ人が別人に見える**）
```

★ 影響は現在値だけではない。`person_profile_revisions`（変更履歴）にも
見えない空白が残っていた。**履歴は後から読むものなので、現在値だけ直しても足りない。**

#### 「同じ打ち方」の意味は、見た目ではなく結果だと読んだ

★ 表とフォームは**作りが違ってよい。** 表は行をまとめて1回で送り、結果を
行ごとに返す（判定はサーバ）。フォームは1件なのでブラウザに即座に弾かせてよい。
だから `type="email"` は**フォームだけ**が使う ―― 表に付けると、1セルの不備で
ブラウザが送信そのものを止め、**どの行が悪いかを返せなくなる。**

★ 表の列宣言に `type: 'email'` があったが、**描画で無視されて text に落ちていた**
（宣言が嘘をついていた）。打ち方だけ揃えるため `inputMode="email"` を効かせ、
`type="email"` にはしない（上の理由）。宣言した型が全部描画に効いていることを
テストで固定した。
