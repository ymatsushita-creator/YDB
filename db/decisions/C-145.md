### C-145. ★ C-121 の名乗りが、本番では効いていなかった ―― プーラが上書きしていた

0038 を本番へ当てたとき、帳簿の末尾がこう出た。

```
適用後 ―― 最後は 0038_staff_sign_in.sql（2026-08-14 01:25:59 JST ・ Supavisor）
```

**`Supavisor` はこちらの道具の名前ではない。** Supabase のプーラである。
本番の接続はプーラ経由で、**`application_name` をプーラが自分の名前へ上書きする。**
0036〜0038 の3件は、どれも `applied_by = 'Supavisor'` になっていた。

★ C-121 で「同じコマンドでも実行が違えば名前が違うので、自分か他人かが分かる」と
書いた仕掛けは、**本番では最初から機能していなかった。**
手元の PGlite では効いていたので、テストは通っていた ――
**動く場所と動かない場所の違いを、テストが跨げていなかった。**

#### 直したもの

```
migrate(db, { actor })   名乗りを**呼び出し側から渡す**。渡されなければ
                         接続の application_name に落ちる（前からの経路を壊さない）
db:migrate:production    actorName() を渡す（道具・pid・機械）
```

★ **経路の途中にあるものが書き換えられる値を、記録の当てにしない。**
これは 0017 の「導出値を直接 UPDATE しない」と同じ性質の話で、
**誰が書いたかを、書いた側の申告として持つ**ということである。

★ すでに `Supavisor` で入った3件は**直さない。** 帳簿は追記の記録であり、
後から名乗りを書き換えれば、それは記録ではなくなる。**間違った名乗りが
残っていること自体が、この日の事実である。**

検証: `tests/51_migration_provenance.test.ts`（**プーラの名乗りを真似た接続でも
渡した名乗りが残る**／渡さなければ接続の名乗りに落ちる／本番の道具が渡している）。
