### C-119. 応募管理表と画面を突き合わせて、抜けを潰した（実行⑬の点検）

依頼者の指示 ――「面接シート以外のフォームがスプシ形式になっているか／
表に必要のない項目がないか／エクセルにある内容でDBにないものはないか／
詰めていない階層がないようにテスト」。

#### ① 入力者を追加を表（スプシ形式）にした

`/staff/new` だけが1件ずつの素のフォームで、**まとめて足せず、打ち間違いも直せなかった。**
表にして、既存の入力者も同じ表に並べた（読むための表を別に持たない）。
名前を直す `renameStaff` を足したが、判定は `addStaff` と同じ規則である
――**表のために判定を書き直さない。** 同姓同名は止めないまま（C-96）。

★ 名前は職員の同一性そのもの（見分ける手段が名前しか無い）なので、直すと過去の
「記録した人」もその名前で読まれる。それでも直せるようにしたのは、**直す道が無いほうが
害が大きい**ためである ―― 打ち間違えた名前は選択肢に残り、選ぶたびに間違いが増える。

★ 残っているフォーム（依頼者の判断待ち）――
`/approach/new`（団体の新規作成。写真と最初の接触を伴う）、
`/people/{id}/edit`（1人の詳細。一括の表は `/people/new` が持つ）、
`/applications/{id}`（採点と判定。面接シートに近い）。

#### ② 表の列は減らしていない

`/people/new` と `/approach` の列を1つずつ見たが、**どれも記録層の値に対応している。**
出ていて記録に行かない列・使われない列は無かった。減らす対象が無い。

#### ③ 応募管理表にあってDBに無かったもの ―― **実データの数で決めた**

`011_提携団体` を列ごとに数え、**入っている件数**で足すかを決めた（0034）。

```
足した    担当部署 168/179 ・ 社内担当 41/179
足さない  所在地・SNS・関連URL  0件（列はあるが1件も入っていない）
          推薦可能人数          2件
        ★ 最適連絡時期        138件あるが 126件が「1.0」―― 読めない値を列にしない
          推薦枠ステイタス      41件。**期ごとの状態**で、団体の現在値にすると期をまたげない
          AWARDへの応募有無     160件。**特定のイベントへの参加**であって団体の属性ではない
          関連するアカデミア生   139件。**人への参照**を氏名の文字列で持つことになる
```

後ろの3つは置き場所を決める必要があるので、指示を仰いでから足す。

★★ **足した列を、テストが1つ捕まえた。** 表の保存は `btrim($n)` で空白を落としていたが、
`btrim` の既定は**半角スペースだけ**なので、全角スペースだけの値が「空ではない」ものとして
残り、`*_not_blank` に弾かれて**行ごと保存できなくなっていた。**
落とす空白を制約と同じ集合にそろえた（0015 の教訓が、制約の無い既存列では
「見えない値が静かに溜まる」形で潜んでいた）。

#### ④ ★ 入る道の無い階層が2つあった

`tests/49_reachable_layers.test.ts` を足して、**画面はあるのに入り口が無いもの**を数えた。

```
/reach-zones/{id}   パンくずに「連携団体 › 団体名」を出しているのに、
                    **どこからもリンクされていなかった** → 団体を開いた先から繋いだ
/pilot              試運転の手順。入り口が無い。画面自身が「終わったら消してよい」と
                    書いているが、**こちらの判断で消さない**（Pilot は HOLD で手順は
                    まだ走っておらず、依頼者に見せた画面でもある）。
                    消すか繋ぐかは依頼者の判断 ―― それまで「知っている孤立」として数える
```

★ 検査を2度間違えた。**リンクの書き方で拾い漏らして**繋がっている `/funnel` を孤立と数え
（`href={to('/funnel')}` の形）、次は**自分から自分へのリンクを入り口と数えて** `/pilot` を
見逃した。**孤立を見つける検査が、孤立を隠していた。**
