### C-61. 2期の取り込み経路を作った ―― 止めているのは生年月日だけではなかった

依頼者の判断（実行⑩）――「生年月日を集める」「取り込み経路を先に作る」。

`HANDOFF.md` は、2期の投入を止めているのは `persons.birth_date` の
NOT NULL だと書いていた。**実際に旧 61 件を突き合わせたら、壁は4つあった。**

```
旧 youth_candidates 61 件 ―― 入る 0 件

  55 件  姓・名（氏名が姓と名に分かれていない）
  61 件  生年月日（旧データに列そのものが無い）
  31 件  メール（persons.email は NOT NULL）
  13 件  学校（persons.school_id は NOT NULL）

  4つすべてそろっている行は 1 件も無い
```

**生年月日だけを集めても、1件も入らない。**

#### 区切りの無い氏名を、勝手に切らない

61 件のうち姓名の区切りがあるのは 6 件だけだった。
「架空太郎」は 架空/太郎 とも 架空太/郎 とも読める。ここで当てにいくと、
同一人物の判定 `(family_name, given_name, birth_date, school_id)` が
**人によって違う切り方で並ぶ。** 切れないものは切れないと返す。

#### 応募日が無い行に、応募日を作らない

応募日があるのは 34 件。無い行（「応募前」など）は**人だけ入れて応募を作らない。**
`applications.submitted_at` は NOT NULL だが、埋めれば応募日が創作される。
**応募が無いことは事実である。**

#### 判定を DB から切り離した

`src/import/legacy_2026.ts` は DB に触らない。触るのは
`scripts/import-legacy-2026.ts` だけである。分けたのは、
**入る／入らないの判定を本番へ繋がずにテストできるようにする**ため。
実データはテストに使えない（CLAUDE.md）ので、判定だけを架空の行で固定した。

#### 既定は書かない

```
pnpm import:legacy:2026              突き合わせだけ（既定）
pnpm import:legacy:2026 --worksheet  足りない値を埋める表を書き出す
pnpm import:legacy:2026 --apply      実際に入れる
```

取り込みは一度きりではなく、値がそろうたびに何度も走る。走らせるたびに
書かれると、そろっていない段階で中途半端に入る。冪等 ――
応募は `form_response_id`（`legacy:youth_candidates:{旧ID}`）、
人は記録層の一意索引で重ねない。`--apply` は開発サーバが動いていれば止まる。

出力は**旧IDと件数だけ**。氏名もメールも出さない。
`--worksheet` は氏名を含むので、gitignore 済みの `db/private/` にしか書かない。

同じものを指すか未確認である（`HANDOFF.md` ③）。
