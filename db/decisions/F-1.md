# F-1

### F-1. 「クライアント JavaScript を配信していない」は事実と違った ★記録の訂正

`HANDOFF.md` の技術構成にこう書いてあった。

> Next.js App Router（**サーバコンポーネントのみ、`'use client'` が0件**）。
> クライアント JavaScript を一切配信していない。

**前半は正しく、後半は誤りである。** 実行⑥で書き込みを足す前に、
それがクライアント境界に触れるかを確かめようとして気づいた。
配信されている HTML を見ると `<script src>` が並んでいる。

```
/_next/static/chunks/…react-dom…js
/_next/static/chunks/…react-server-dom-turbopack…js
…（開発サーバでは next-devtools も）
```

App Router は RSC のペイロードを流し込むために React の実行時を必ず配る。
`'use client'` が0件でも「JS を配信していない」ことにはならない。

**この誤りが何を招きかけたか。** 「JS を1バイトも配っていない」という前提で
考えると、フォームの送信すら境界の新設に見える。実際には素の
`<form action={...}>` はサーバコンポーネントに置けて、`'use client'` は
0件のままである。**誤った前提のほうが、判断を過剰に保守的にしていた。**

正しい言い方はこうなる ―― **クライアント部品を1つも書いていない**
（`'use client'` が0件で、状態を持つ対話部品が無い）。
`HANDOFF.md` の当該行はこの版で直した。

計測は `curl` で配信 HTML を見るだけでよい。

```bash
curl -s http://localhost:3111/cockpit | grep -o '<script src="[^"]*"'
```

なお上は `next dev` の出力である。**本番ビルドで何が配られるかは測っていない。**
開発サーバは devtools を足すので、少なくともその分は本番と違う。
「本番では0件になる」とは書けない（測っていないことを書かない）。
