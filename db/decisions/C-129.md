### C-129. 打ち消しの道を全数点検した ―― **4つのうち画面から打ち消せるのは1つ**

依頼者の指示（実行⑮）――「**訂正の道が無い記録を潰す**」。

CLAUDE.md は「追記専用テーブルの訂正は打ち消し行で行う」と定めている。
その打ち消し列（`corrects_*`）を持つ記録を数え上げると4つあり、
**道が画面まで通っていたのは1つだけ**だった。

```
記録                            記録層  コマンド            画面
status_histories （0001）        ある    correctDecision     ある（応募の頁）
approach_events （0016）         ある    ★無い              ★無い
person_notes （0027）            ある    ★受け口だけ        ★無い
partner_recommendation_events    ある    ★無い              ★無い
（0035）
```

★ `person_notes` は**コマンドが `correctsNoteId` を受け取れるのに、
渡していたのはテストだけ**だった（`tests/39`）。形はあったが、
運用者の側から見れば無いのと同じである。

★ **規律に書いてあることが、画面でできないままだった。**
「訂正は打ち消し行で行う」は運用の作法なのに、その作法を実行する手段が
SQL しかない ―― これは記録層の欠陥ではなく、**道の欠陥**である。
