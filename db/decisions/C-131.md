### C-131. 打ち消しの道を画面へ通した（メモ・アプローチ状態・推薦枠）

C-129 で見つけた3つに道を通した。**打ち消し行の形は `correctDecision` に
そろえた** ―― 打ち消し行が**正しい値を載せて元に取って代わる。**
元の行は記録層に残り、有効判定のビューから落ちるだけである。

```
メモ            /borderline のメモ ―― 各メモに「取り消す」を畳んで置いた
                取り消す人と理由は**記入必須**（元のメモと同じ規則）。
                打ち消し行の本文が**取り消した理由**として一覧に残る ――
                行がまるごと消えて、あとから見た人が「そこに何かあった」
                ことすら分からない状態にしない
アプローチ状態   /people/{id}/edit ―― 同じ欄のまま**押すボタンで意味が変わる**
                「状態を記録」＝出来事を積む／「直前を訂正」＝打ち消して置く
推薦枠ステイタス /reach-zones/{id} ―― **置くのは表、直すのは団体の頁**
                （表は行をまとめて送るので、行1つに閉じた操作には向かない）
```

★ **なぜ置き直しでは足りないか** ―― 0035 のテストが書いたとおり、
出来事を積むことには「**その日に動きがあった**」という意味がある。
打ち間違いを置き直しで直すと、動いていない日が動いたことになる。

★ **終端の状態を押し間違えたら戻れなかった。** 見送り（`approach_states`
の `is_terminal`）と対象外（推薦枠）は「これ以上こちらから動かさない」状態で、
訂正の道が無いと、その人・その団体は**一覧に二度と現れない。**

★ 打ち消す相手は**コマンドが記録層から引く。** 画面から出来事の ID を
渡させない ―― 古い画面を開いたまま押したときに、**見ていない行を
打ち消せる。** メモも同じで、渡すのは note の ID だけで、人は記録から引く。

★ **「置いていない」へは戻せない。** 状態は NOT NULL で、記録の無さを
表す行は作れない。誤って置いた団体は正しい状態へ訂正する。
これは記録層の形からくる制限なので、**画面で誤魔化さない**（訂正する相手が
無ければ `nothing_to_correct` を返し、「置く」ほうへ回す）。

★ `'use client'` は**増えていない**（C-95 / C-104）。取り消しの畳みは
`<details>`、ボタン2つは `formAction` で、どちらも素の HTML である。
