### C-42. ヘッドハンティング画面を作った。外枠を2つに分けた

実行⑨。依頼者の画像の構造をそのまま作った（`/headhunting`）。

#### 外枠を2つに分けた理由

画像の外枠（暗い操作柱＋オレンジの階層バー）は、既存9画面の外枠
（白い操作柱＋細いツールバー）と別物である。1つに畳もうとすると
どちらかの意匠が崩れる。**依頼者が決めたのはヘッドハンティング画面の
意匠であって、既存9画面をそれに合わせろとは言われていない。**

`app/layout.tsx` を `<html>` と読み込みだけに減らし、既存9画面を
ルートグループ `app/(workspace)/` へ移した。**ルートグループは URL を
変えない**ので、`/cockpit` などの経路は元のままである
（`pnpm build` のルート一覧で9画面すべてを確認した）。

#### 画像にあって、作らなかったもの

**画面の下に一覧として出してある。** 黙って省くと、次に触る人が
実装漏れと読んで作り直しにかかる。

| 画像の要素 | 出せない理由 |
|---|---|
| 顔写真 | 記録層に無い。加えて「個体を描くときは個人を漏らさない」 |
| 学年・卒業年度 | 列そのものが無い。生年月日も実データには0件 |
| 職種での絞り込み | 記録層に無く、定義も未受領 |
| 成績ランキングの順位変動 | 過去の順位を凍結していない（凍結しているのは確度だけ） |
| 手で作るタスク | タスクの記録層が無い（D-12 の TODO(MVP) 2） |
| 期限の時刻（14:00 まで） | 目安は日単位。時刻を作ると記録より画面が精密に見える |
| ログアウト | 認証がまだ無い |

**同じ見た目の矢印を、片方だけ作り物で埋めない。** 確度には
凍結された過去があるので順位の変動を出せるが、成績には無い。
成績の側にも矢印を置けば見た目は揃うが、それは数字の捏造である。

#### 星は比で塗り、素点を必ず併記する

軸の満点は年度で違う（16点満点の軸も5点満点の軸もある）ので、
星は比に直して塗る。**絵だけにすると、丸めた見た目が事実になる**
（実行⑥で「表示の丸めで注記が嘘になる」を踏んでいる）。

#### 動かして見つけた欠陥3件

1. **React の key が衝突していた。** 同じ人・同じステップ・同じ種別の
   やることは2件あり得る（二次面接に面接官が2人）。人とステップの組を
   鍵にすると2件が畳まれる。`source_id` に変えた。**コンソールの
   エラーで見つかった。画面を目で見ても、行は2行出ていた。**
2. **助詞が壊れていた。**「書類選考を担当を替える」。種別ごとに助詞が
   違うのに1つの型で作っていた。種別ごとの文にした。
3. **成績ランキングが同率1位だらけだった。** 1軸だけ満点の人と
   6軸を通して高い人が、どちらも100.0 になる。順位は定義どおり同率の
   ままにし、**点が付いた軸の数を列として出した。** 根拠の薄さが
   読めない一覧は、順位として意味を持たない。

#### 確かめ方

デモ経路（`pnpm dev:demo`）で DOM の値を読んで確認した ――
やることの文・成績の軸数・確度の順位と変動・アプローチのチップ4種・
候補者を選ぶと右のパネルとリストの強調が連動すること・
対象者が0人の年度で全カードが空の理由を文で出すこと。
画面に内部の識別子が出ていないことは `grep` で検査した（C-32 / C-37）。
`pnpm test`（333件）・`tsc --noEmit`・`pnpm build`・`pnpm tokens` を確認した。
