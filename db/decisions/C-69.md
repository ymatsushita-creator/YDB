### C-69. 面接シートを作った（0022）

依頼者から様式を受領（実行⑩）―― 評価軸6つ（各1〜4点）、記入欄10、
最終判定3択、判定補足。**変更ログが残ること。**

#### 評価軸は作らなかった。**すでにあった**

笑顔・リスペクト・前提超越・熱量・地頭力・素直さ は
`evaluation_criteria`（2期・最終面接、各4点満点）に登録済みで、
点と根拠は `evaluation_scores` に入る。**同じ軸を2箇所に持たない。**

シートが受け持つのは、**点では表せない記入欄と判定**だけである。
`interview_sheets` に点の列は1つも無い ―― テストで列の一覧ごと固定した。

★ 画面は**6軸と決め打ちしていない。** その段に登録されている軸をそのまま出す。
決め打ちすると、軸が2つのデモ年度で4つ空欄が並ぶ。

#### 面接官も作らなかった

`evaluations.interviewer_staff_id` にある。シートに写すと、
担当を替えたときに**シートだけ古い面接官を指す。** 評価から辿る。
テストで、担当を替えたらシートの表示も動くことを固定した。

#### 面接日は新しく持つ

`evaluations` にあるのは割当時刻と提出時刻で、どちらも面接をした日ではない。
**近い値で代用しない。**

#### ★★ 最終判定は、選考の判定ではない ★★

選考の通過／不合格は `status_histories` にあり、そこに**「ボーダー」は無い。**
シートに入るのは面接官の所見であって、組織の決定ではない。
混ぜると、誰がいつ決めたのかが辿れなくなる。

だから列名も `verdict` ではなく `recommendation` にした。
テストで「所見を書いても `status_histories` が1件も増えないこと」を固定している。

#### 変更ログ

現在値は `interview_sheets`、書いた後の**全体像**を
`interview_sheet_revisions` へ1行積む（0018 と同じ形）。差分にしない ――
差分だと、読むときに全部を頭の中で再生しないと当時の姿が分からない。

**現在値と変更ログは同じ回で書く。** 片方だけ書ける道を作らない。
ログは追記専用（`reject_mutation`）で、上書きも削除もできない。

#### 1つの面接 = 1つの評価

面接官が2人なら評価が2件でき、**シートも2枚**になる（UNIQUE (evaluation_id)）。
だから URL の鍵は評価の ID である。応募でも候補者でもない。

#### どこから行けるか（依頼者の指示）

```
ヘッドハンティング  氏名 → /people/{id}          → 面接シート
ボーダーライン      氏名 → /borderline/{personId} → 面接シート
名前検索            氏名 → /people/{id}          → 面接シート
応募の経緯          段の名前 → 面接シート
```
