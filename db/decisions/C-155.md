### C-155. イベントを追加する表（依頼者の指示）

依頼者の言葉（実行⑯）――「連携団体を追加タブの下に、イベントを追加タブを作成。
これもスプシ形式で、**内容はエクセルを見て決めろ**」。

#### 列はエクセルから取った

`4月イベント一覧` の見出し ――
**参加有無 / イベント名 / 日程 / 時間 / 場所 / 対応者 / URL（あれば） / 備考**

```
イベント名 → appointments.title
日程       → starts_at / ends_at の日付
時間       → **開始と終了に割った**
場所・URL・備考 → note へ**見出しごと**
対応者     → owner_staff_id
参加有無   → 扱わない（下）
```

★ **「時間」を開始と終了に割った理由。** `ends_at` は NOT NULL である。
表に終わりが無いとき「2時間くらいだろう」で埋めれば、それは記録ではなく推測になる。
**終わりの時刻は作らない** ―― 無ければ入れずに理由を返す。

★ **「参加有無」はこの表では扱わない。** 参加は接点（0028）であって
イベントの属性ではない。カレンダーから参加者を記録する道が既にある ――
同じ事実を2箇所に置かない。

★ **場所と URL のために列を作らない**（0035 と同じ判断）。記録へ見出しごと残す。
繋げて書くと、あとからどれが場所でどれが URL か読めなくなる。

#### 置き場所は予定（0019）。新しい表を作らない

イベントは「いつ・どこで・誰が対応する催し」で、予定と同じ形をしている。
別表にするとカレンダーが2つの表を混ぜて読むことになる。
既存の種別6つは候補者必須か社内MTGで、集客イベントを置ける種別が無かったので
0040 で `event`（`requires_person = false`）を1つ足した。

★ 表は**足すだけ。** 予定の書き換えは変更履歴（`appointment_revisions`）を伴う
別の道で、そこを表から呼ぶと版番号の付け方が2箇所に散る。
**直す道が無いことは画面に書く**（黙って効かない列を出さない）。
