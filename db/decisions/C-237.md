## C-237 候補者の登録を「姓だけ必須」にした（未選択は非活性の行へ寄せる）

**2026-08-24。依頼者の指示** ―― 表からの一括投入で 17 行が落ちた。
「なんではいんないの？」「じゃあ、必須ではなくしてほしい」
「名前さえ入れてれば後は未記入でいいに決まってんだろ」。

### 何が起きていたか

判定は正しく働いていた。`addCandidate` は姓に加えて**学校・流入元・入力者**を
必須にしており、表の 17 行はその3つが未選択だった。落ちた理由は行ごとに
表の下へ出ていた（`app/_components/sheet.tsx`）。**バグではない。**

そのうえで依頼者は必須を外すことを選んだ。以下は緩和の作り方の判断である。

### NOT NULL は外さない

外していない。0023 が学校について既に検討して却下している ――
`persons.school_id` を NULL 可にすると **9箇所の内部結合で学校の無い人が
一覧から黙って消える。消えるのは、無いと書くより悪い。**

同じ理屈が流入元にも効く ―― 接点を作らない行が出ると、流入元別の合計が
候補者数より少なくなり、**ズレの原因が後から追えない。**

したがってこの2つは **記録層を変えず、非活性のプレースホルダ行へ寄せた**（0054）。
0023 の「学校未記録」と同じやり方である（原則3: 集計マスタは更新せず
追加と非活性化で運用する）。

```text
schools 「学校未記録」    0023 で既に在る
channels「流入元不明」    0054 で足した
```

**非活性なので選ぶ画面には出ない。** 運営が「不明」を選べるようにした変更では
なく、未選択のまま保存したときに裏で寄る先である。名前は後から書き換えない
（書き換えると過去の記録の意味が変わる）。

### 入力者だけはプレースホルダを作らなかった（作って壊した）

**最初は同じやり方で「入力者未記録」という職員の行を1つ置いた。壊れた。**

```text
tests/22_reference_season.test.ts  本番シードは staffs を0行に保つ
                                   ―― 氏名が origin と mirror へ push されるのを防ぐ壁
tests/52_season3_alignment.test.ts 職員が1人でも居ると 0007 の
                                   目標応募数の引き継ぎが走ってしまう
```

どちらも緩めてよい検査ではない（`AGENTS.md`「検査を通すために検査の側を緩めない」）。
**居ない人を作るほうが間違っていた。**

`approach_events.recorded_by_staff_id` を NULL 可にした。学校や流入元と違い、
**この列には誰も内部結合していない** ―― `v_person_approach_state` と
`v_headhunting_list` は列を通すだけで `staffs` に結合せず（0016）、
`src/queries/` は読んでもいない。したがって NULL にしても人は一覧から消えない。
`form_responses.matched_by_staff_id` は 0025 から既に NULL 可である。
`partner_recommendations.recorded_by_staff_id`（0035）は触っていない ――
あちらは画面が必ず職員を選ぶ。

**NULL は「誰が入れたか分からない」であって「誰も居ない」ではない。**

### 未選択と「形が違う値」は別に扱う

未選択は寄せるが、UUID でない値・実在しない UUID は**今まで通り落とす。**
黙って別の行へ入れない。寄せ先の行そのものが無いときも落とす。

### 入力者を「いま入っている職員」に寄せなかった理由

依頼者に問うたとき「そもそもログイン中の人は判別しない設計では？」と返った。
**そのとおりである。** 券は `staffId` を持てるが（0038）、`app/login/actions.ts`
は `issueSession(secret, tier, Date.now())` と呼んでいて第4引数を渡していないので、
`currentStaffId()` は常に null を返す。仕組みだけ在って配線されていない。
配線した日に、プレースホルダより券を先に見る。

### 効く範囲

判定は `src/commands/intake.ts` の `addCandidate` 1箇所なので、**表（`/people/new`）と
1人ずつの登録の両方に同時に効く。** 画面によって通る値が違う状態は作らない。

### 残っている問題（この判断では直していない）

必須が消えたので今回の投入は通るが、**表が保存前に何も言わない**点は変えていない
―― 未入力セルは赤くならず、上の要約は件数だけである。必須が無くなった今は
弾く物も無いが、流入元が「不明」に寄った行が何件出たかは画面に出ない。
