### C-43. 情報構造を3つのタブに集約し、年度を最上位に上げた（依頼者の指示）

実行⑨。C-42 で作った版に対し、依頼者から4点の指摘が出た。
**いずれも「md と矛盾するなら md を書き換えろ」という指示付きだった。**

| 指摘 | 直したこと |
|---|---|
| 年度がヘッドハンティングの**下の階層**に並ぶのはおかしい | 年度を最上位に上げ、**全タブ共通の帯**にした |
| 募集は **2025 と 2026 しか行われていない** | デモの年度を 4 → 2 に減らした |
| 画像は**ヘッドハンティングだけの画面ではない**。横タブもその要素 | 外枠を**全画面共通**にした |
| **「運転席」という名前を削除** | ボーダーラインに改名した |
| ファネル・森と流入元のようなタブは**消せ**。情報は3タブに集約 | 行き先を3つに固定し、他は各タブの中へ畳んだ |
| **名前検索を勝手に消すな** | 操作柱に戻した（素の form。JS 無しで動く） |
| ボタンは**物理ボタン**に | 厚みと沈み込みを付けた（`btn-physical`） |

#### 年度が最上位である理由

タブより下に置くと、**タブを移った瞬間に見ている年度が変わる。**
3つのタブが別々のアプリになり、「同じ年度の話をしている」という前提が壊れる。
帯はどのタブでも同じ位置にあり、切り替えても同じタブに留まる
（`basePath` を各画面が渡すのはこのため）。

#### 年度は記録層にある行だけを出す

デモは 2024〜2027 の4年度を作っていた。**募集が行われていない年度が
画面の切替に並ぶと、運営に「その年度の記録がどこかにある」と思わせる。**
デモが架空データであることと、存在しない年度を見せることは別の問題である。

2025（終わった年度）と 2026（進行中）の2つにした。
**この変更で、デモが踏んでいた経路が2つ壊れた。**

1. 「年度に紐づかない接点」が**1件も無くなった。** 年度の窓の外に落ちる
   接点は、これまで乱数の裾で偶然できていた。窓の数が減ったら消えた。
   **偶然に頼っていた経路は、条件が変わると黙って消える。**
   2025年度の終わりと 2026年度の始まりの谷に、明示的に1件置いた
2. 「再応募して合格した人」と「判断待ちが十分ある」が両立しなくなった。
   2026 の応募期間を締切間際まで延ばして、**早く応募した人は選考が終わり、
   遅く応募した人は途中で止まっている**状態にした

#### 3つのタブへの畳み方

```
ヘッドハンティング  /headhunting   誰に声を掛けるか（＋ /people 人を探す）
ボーダーライン      /borderline    誰を通すか（旧 運転席。＋ /operations /applications /pilot）
アプローチ          /approach      どこから来ているか（旧 森と流入元。＋ /funnel /forests）
```

**どの画面がどのタブに属するかは、そのルートの `layout.tsx` が宣言する**
（`<Shell active="borderline">`）。畳んだ先がファイルに書かれているので、
次に触る人が「この画面はどこから辿れるのか」を読める。

#### `'use client'` は0件のまま

いま居るタブを知るのに `usePathname()` を使うとクライアント境界が要る。
**代わりに各ルートの layout.tsx が自分のタブを名乗る形にした。**
境界を1つも増やさずに済み、しかも畳んだ先が構造として残る。
名前検索も素の `<form action="/people" method="get">` なので JS 無しで動く。

#### 上位文書を書き換えた

依頼者の指示に従い、**`director.md` と `design.md` を改定した。**

- `director.md` —— 「最上位オブジェクトは Forest」「人が最上位に来る UI は禁止」
  「一覧を増やさない」「テーブルを作らない」「一覧→詳細は禁止」を撤回
- `design.md` —— Navigation を3タブに、`Never: List → Detail` を撤回、
  Core Components を**実装のある部品**に置き換え
- `CLAUDE.md` —— 3節に「画面の最上位は年度と3つのタブ」を新設（以降を繰り下げ）

**改定前の条文は各文書に引用として残した。** 消すと、なぜ実装がこうなって
いるのかを次に読む人が追えなくなる。また、繰り下げで節番号がずれたので、
`CLAUDE.md n節` を参照していた6箇所を機械的に直した
（**参照が嘘になると、読んだ人は確認をやめる**）。

#### 確かめ方

`pnpm test`（333件）・`tsc --noEmit`・`pnpm build`（全ルートの生成を確認）・
`pnpm tokens`。画面はデモ経路で3タブとも DOM とスクリーンショットで確認した。
年度が2つだけ出ること、タブを移っても年度が保たれることを含む。
`tests/22_reference_season.test.ts`「サンプルの環境にデモを入れても年度が衝突しない」
が年度の一覧そのものを固定している。
