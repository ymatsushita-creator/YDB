### C-63. 個人名から採点できるレイヤーを作った

依頼者の指示（実行⑩）――「採点者が採点する時に打てるように、
個人名押したら採点できるレイヤー作れ」。

C-59 で選考タブの右パネルに採点を置いたが、**それは一覧の付属物である。**
面接中に開くのは候補者1人の採点用紙であって、一覧の右端ではない。

```
/borderline/{personId}?season=…&tab=…
```

#### 段で絞らない

一覧のタブは「いまその段に居る応募」しか出さない。
レイヤーは**その期のその人の評価をすべて**並べる。確定済みも落とさない ――
**前の段で何点だったかを見ずに、次の段は付けられない。**

#### 入口が2つでも、規則は1つ

採点シートは `app/_components/scoring.tsx` に出し、
一覧の右パネルとレイヤーが同じ部品を使う。判定は
`v_open_tasks` と記録層の CHECK / トリガにあり、画面側は持たない（C-25）。

戻り先は打った場所へ返す。`layer` を立てて区別している ――
一覧から打ったら一覧へ、レイヤーから打ったらレイヤーへ。
**採点した相手が画面から消えない。**

#### 確定済みに「止まっている理由」を出さない

`blocked_by` は確定済みの評価に対して「この応募はもう動いていない」と言う。
止まっているのではなく**終わっている**ので、嘘に読める。
確定済みのときは出さず、「確定済み」だけを出す。

#### 押す先で行き先が違う

```
氏名        → 採点レイヤー
行の「›」   → 確度順ならその人の記録、選考タブならその応募の経緯
```

#### 確かめ方

`tests/33_borderline_scoring.test.ts`（13件）。
段で絞らないこと・期をまたがないこと・削除済みの人が出ないことを固定した。
画面では、レイヤーから1軸を保存して**同じレイヤーへ戻る**ことを確かめた。
