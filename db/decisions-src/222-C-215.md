## C-215 パイロット試験は、本番も開発用DBも触らない別のDBで回す

依頼者の指示（実行⑱）――「選考を行う平社員のペルソナを5人作って、2期生の
データを使って、同時に模擬選考を行ってくれ。終わったら、今回の選考は消してね」。

`.env.local` の `DATABASE_URL` は**本番（Supabase）を指している。** そのまま
`pnpm dev` を起動すると、模擬選考が本番の帳簿へ入る。しかも選考の記録は
追記専用で、入れたら消せない（原則5。実際に `status_histories` の DELETE は
トリガに拒まれた）。だから模擬選考は**捨てるDB**の中だけで行う。

- `src/db/server.ts` に `YOUTHDB_PGDATA` を足した。指定が無ければ従来の `.pgdata`。
- `.claude/launch.json` の `youthdb-pilot` は `DATABASE_URL=` を空にし、
  `.pgdata-pilot` を開き、パイロット専用の合言葉で入る（3113番）。
- `scripts/pilot-db.ts` が段・軸・書類選考10点という**実在の構造**の上に
  **架空の候補者15人**を置く（`scripts/simulate-selection.ts` と同じ境界。C-36）。
  人を作るのは画面と同じ `addCandidate` である ―― 直に INSERT すると接点と
  アプローチ状態が付かず、一覧に1人も出ない。
- 2期は終わった期（選考終了 2026-04-15）なので、識別日・接点・応募日を
  **2期の窓の中**へ置く。今日のままだと `v_person_season_state` の
  「識別日 ≦ 選考終了日」に外れ、「年度ごとの現在地」に2期の行が出ない。
- 「消す」は**そのDBを作り直すこと**である。追記専用の帳簿は DELETE できない。

★ 2期の実在応募者は入れていない（CLAUDE.md「実在個人情報をデモ、テスト、
スクリーンショットへ使わない」）。**構造は実物、人は架空**である。

検証: `tests/78_pilot_hirashain.test.ts`。4周とも本番へは1件も書いていない。
