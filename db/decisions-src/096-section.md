### C-47. 記入できる場所と固定の場所を色で分けた

実行⑨。依頼者の指示 ――
**「記入ができる画面と、固定の画面を区別して色を分けて」**

画面はどこも白いカードで、**書き込める場所と、記録を映しているだけの
場所が同じ見た目**だった。見分けが付かないと、書けない値をいじろうとするか、
書ける値に気づかないまま帰る。

#### 3段階で分けた

| | 見た目 |
|---|---|
| 記入できる領域（ブロック） | 淡い青の面＋縁。上に `記入できます` |
| 記入できる入力（行の中） | 面は塗らず、**入力の縁だけ**色を変える |
| 書き込む場所が無い画面 | 現在地の帯に `固定 この画面は記録を映すだけ` |

行の中の小さなフォームに面を敷かなかったのは、**表の行に色が付くと
行そのものが状態を持っているように読める**ためである。
評価の点を入れる欄が「注意が必要な行」に見えてはいけない。

**色だけで意味を伝えていない。** どの印にも文字が付いている。

色は `basic/DESIGN.md` に `editable` / `editable-border` / `editable-ink`
として足し、`pnpm tokens` で生成した（直値で書かない）。

#### 印は人が付けるので、機械に見張らせる

`readOnly` も `editable-region` も手で付ける印である。
**フォームを1つ足した日に `readOnly` を外し忘れると、画面が
「書けません」と嘘をつく。** 嘘の注記は、注記が無いより悪い ――
読んだ人が探すのをやめるからである。実行⑥から何度も踏んでいる形なので、
人の見直しに頼らない。

#### 確かめ方

`tests/30_editable_marking.test.ts`「「記録を映すだけ」と書いた画面に、記入できる領域が無い」
「記入できる領域には、必ず印のクラスが付いている」。
最初この検査は、コメント内の説明（`<form action={...}>`）を実装として
数えて落ちた。走査前にコメントを落とすようにした。

加えて全ルートを HTTP で引いて突き合わせた ――
記入できる画面（`/headhunting` `/borderline` `/applications/[id]`）に
固定の印が無いこと、固定の画面（`/approach` `/funnel` `/operations`
`/pilot` `/people` `/people/[id]`）に記入できる領域が無いこと。
`/applications/[id]` は**同じ画面でも記録の状態によって書ける／書けないが
変わる**ため、固定の印を付けていない（付けると状態によって嘘になる）。
