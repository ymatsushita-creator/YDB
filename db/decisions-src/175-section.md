### C-124. デプロイ先を道具で照合する ―― 文書だけで守るのをやめた

依頼者の指示（実行⑭）――「君が決めて」。
C-123 で「接続先は gitignore 済みなので見張れない。文書に置いた」と書いた。
**その弱いところを、こちらの判断で塞いだ。**

```
pnpm deploy:production   .vercel/project.json を読み、約束した先かを照合し、
                         名乗ってから vercel --prod --yes を渡す
```

#### 何を照合するか ―― 名前ではなく指紋

**名前だけでは足りない。別のアカウントに同じ名前のプロジェクトを作れる**
（今回の `ydb` / `youthdb` がまさにその形だった）。だから orgId と projectId の
**両方**を見る。ただし公開リポジトリに識別子をそのまま置かない ――
`sha256` の先頭12桁で照合する。**照合には指紋で足りる**ので、足りるほうを選ぶ
（合言葉を記録に書きかけた C-112 と同じ精神）。

#### 迷ったら止める

読めない・壊れている・違う先、のどれでも**デプロイしない。**
間違った本番へ出すより、出ないほうが害が小さい。

★ 判定は `scripts/deploy-target.ts` の純関数に置き、テストの下にある。
`scripts/deploy-production.ts` がやるのは「読む・名乗る・渡す」だけである
（判定を道具の実行経路に混ぜない ―― `src/commands/` と同じ分け方）。

★ **`vercel --prod` を直に打たない。** 打てば照合を飛ばせるので、
規律としては弱い。だが**弱い規律でも、名乗る出口があるほうが強い** ――
`db:backup` / `db:migrate:production` が読み取り先・書き込み先を名乗るのと同じ作法に揃えた。

★ 手元の `.vercel/project.json` があるときは、それも照合する（無ければ飛ばす）。
他の人の手元や CI では別の先を向いていてよい ―― **固定するのは約束のほうである。**

検証: `tests/53_deploy_target.test.ts`（通る／別アカウントで止まる／同名の別
プロジェクトで止まる／読めなければ止まる／**この手元は約束した先を向いている**）。
`pnpm deploy:production` で実際に本番へ出し、「書き込み先 ―― youthdb」と
名乗ってから Ready になることを確かめた。
テスト … `tests/53_deploy_target.test.ts`
