### C-123. 本番は `youthdb`（yuzy742's projects）である ―― 画面の `ydb` は3日前で止まっていた

依頼者から「デプロイできてる？ Vercelの画面がおかしいだけ？」（実行⑭の最後）。
**どちらでもない。同じリポジトリに Vercel プロジェクトが2つあった。**

```
画面に出ていたもの   アカウント yujis / プロジェクト ydb   最新 d8a8454（3日前）
こちらが流したもの   yuzy742's projects / youthdb        最新 Ready（当日）
```

決め手 ―― **`mirror`（ymatsushita-creator/YDB）の先頭が `d8a8454`** で、
画面の最新デプロイと**同じコミット**だった。`ydb` はミラー側のリポジトリを見ており、
そこへ3日 push されていないので実行⑫⑬⑭の約30コミットが届いていない。
**画面は正しく「3日前が最新」と言っていた。**

#### 依頼者の判断 ―― `youthdb` を本番とする（ミラーへは push しない）

```
本番        https://youthdb.vercel.app（yuzy742's projects / youthdb）
見ない場所   yujis / ydb ―― 古いまま残る。ミラーを更新しない限り動かない
```

★ **テストで固定していない。** 接続先は `.vercel/project.json` にあるが
gitignore 済みで、リポジトリからは見えない（見張りを置けない）。
だから**文書に置く** ―― `HANDOFF.md` の「本番の場所」がそれである。

★ ミラーへ push しないのは公開範囲の判断であって、技術的な制約ではない。
**両リモートは公開である。** 送るかどうかは依頼者が決める。
