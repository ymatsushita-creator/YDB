### C-62. 画面から説明を消し、切れていた中身を送れるようにし、一覧を一覧にした

依頼者の指摘（実行⑩）。5つある。

#### 1. 期に付いていた点を外した

`seasons.is_live`（今日が集客開始〜選考終了の間）を緑の点で出していた。
**何の点なのか画面のどこにも書いていない。** 意味の分からない印は、
意味を推測させるぶんだけ邪魔になる。外した。

#### 2. 説明を全画面から消した

`unit-note` / `footnote` / `Card` の `note` / `readonly-note` ―― 
単位・母集団・集計の定義・タイムゾーンの注記を、画面ごとに置いていた。
**読む相手は運営であって、毎回同じ説明を読まされる相手ではない。**

`CLAUDE.md` の完了条件「数字には単位と母集団を表示」も同時に直した。
定義そのものを捨てたわけではない ―― **置き場所をクエリのコメントと
この文書に移した。** 画面に無いことと、根拠が無いことは違う。

残したもの ―― 担当者メモ、申し送り、根拠エピソード、KPI の単位1語。
**どれも記録であって説明ではない。**

#### 3. 切れていた中身を、送れるようにした

C-57 / C-58 で入れた「位置を固定する」仕組みは、枠が2つ並ぶ
ダッシュボード（ヘッドハンティング／ボーダーライン）のために作った。
**カードが縦に4枚5枚並ぶ一覧の画面にも効いていた。**

その結果、選考オペレーションでは1枚あたりの高さが数行ぶんまで潰れ、
**「面接官別の負荷」も「保留」も見出しだけになっていた。**

一覧の画面は `.hh-grid` を持たない。そこだけ外枠を送る器にして、
カードは中身なりの高さに戻した。**潰さない。並べる。**

★ もう1つ、**送れているのに切れて見えていた**ものがあった。
macOS の既定はスクロールバーを隠すので、行の途中で切れた絵だけが残る。
細い軌道を常時出し、表の見出しを貼り付けた。
**「送れること」は、送れるだけでは伝わらない。**

#### 4. 一覧を一覧にした

確度順候補者リストは1ページ5行だった。48人の期で**10ページ**になり、
「確度順の候補者リスト」なのに**上位5人しか一覧できなかった。**
ページ送りを外し、全件をカードの中で送る形にした。
ヘッドハンティングの2つのランキングも同じ（5件 → 全件）。

併せて**次の層への入口**を置いた。一覧の行から、
確度順は「その人の記録」へ、選考タブは「その応募の経緯」へ。
採点シートからも応募へ行ける。**一覧で終わらせない。**

#### 5. 顔写真をランキングにも出した

応募者成績ランキング・候補者確度ランキング・ヘッドハンティングリスト。
名前だけの一覧より、顔がある一覧のほうが探しているものへ早く着く。

#### 併せて直した比率と余白

日程カレンダーは格子なので、縮むと時間の目盛りごと潰れる。
右列の比率を 1.25 : 0.75 から 1 : 1 にし、カレンダーを伸ばした。
左列は 0.8 : 1.2 から 0.6 : 1.4 へ ―― 一覧に高さを寄せた。
見出しとセクションの余白は 32px から 20px / 16px へ詰めた。
**トークンは変えていない**（意匠の原典は `basic/DESIGN.md`）。

#### 確かめ方

`pnpm test` / `tsc` / `build`。デモ経路で11画面すべて 200。
**「はみ出しているのに、自分も祖先も送れない要素」を DOM で数えて 0 件**
であることを、選考オペレーション・人を探す・ボーダーラインの4タブで確認した。
目で見て「切れていない気がする」で済ませない。
