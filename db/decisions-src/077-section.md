### C-30. デモモード ―― サーバレスで見せるためだけの経路

実行⑦。2026-08-07。Vercel にリポジトリが繋がれ、URL で見せたいという指示。

**そのままでは動かなかった。** `getDb()` は `.pgdata/` を開くが、
このディレクトリは **git 管理外で配られず**、サーバレスの
ファイルシステムは**書き込めない**。

#### 永続を諦めて、起動のたびに組み立てる

`YOUTHDB_DEMO=1`（未指定なら `VERCEL` を見る）のとき、
インメモリの PGlite を開いて `migrate` → `seed(examples)` → `seedDemo` を流す。
手元で測って **1.3 秒**（open 786 / migrate 67 / seed 2 / demo 430）。

**サンプルの環境なので実年度は入らない**（C-28 の境界をここでも保つ）。
創作の応募が実在の 2026年度にぶら下がらない。

#### これは Pilot の本番ではない

判定は押せるが、**インスタンスが入れ替わると消える。**
実データも入っておらず、認証も無い。`DEPLOY-READINESS.md` の
必須7項目（バックアップ・認証・DB の分離ほか）は**1つも満たしていない。**

**画面にそう出す。** URL を渡された人には、これが実データかどうかを
確かめる手段が無い。出さなければ「実在の候補者が26人待っている」と読める。
ツールバーに「デモ ・ 架空データ ・ 保存されません」を赤字で出している。

#### ついでに踏んだ罠

`new URL('../../db/migrations/', import.meta.url)` を Turbopack が
**モジュール参照として静的解決しようとして落ちた。**
`src/db/server.ts` の `DATA_DIR` が同じ理由で `process.cwd()` を
使っていたのに、`migrate.ts` は見落としていた。同じ形に揃えた。

さらに、SQL は `import` ではなく実行時に `fs` で読むため、
**参照が静的に辿れずサーバレスの束に入らない。**
`next.config.ts` の `outputFileTracingIncludes` で明示した。
これが無いとビルドは通るのに、公開先でだけ「ファイルが無い」で落ちる。

テストは 289 件のまま全通過（パスの組み立て方を変えただけで、
テストも `scripts/` もリポジトリのルートから動く）。
`pnpm build` の通過を確認した。
