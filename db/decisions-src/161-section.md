### C-111. 一覧が全件出ていなかった ―― **人を探すが 50 人で切っていた** ★事故

依頼者の指摘（実行⑫）――「一覧できないと意味ねぇだろ」。

本番へ 512 人入れた直後の状態がこれだった ――

```
人を探す        50 人で打ち切り（LIMIT = 50。実行⑩から）
選考オペレーション 40 件で打ち切り（`pending.slice(0, 40)`）
特別選考・通常選考 500 件（実データはまだ入るが、積み上がれば黙って切れる）
```

**どれも画面には何も出ていない。** 出ているものが全部だと読める形だった。
C-62 で「一覧は全件、ページ送りは無い」と決めたのに、
**その決定が届いていない画面が残っていた**（決めたのは実行⑩の後半で、
`/people` の 50 はそれより前に置かれたまま）。

**対応** ―― 上限は残すが、**表示を切るためではなく暴走を止めるための数**にする。

```
人を探す        50 → 2000。**1件多く取り**、超えたら「n 人まで出している」と画面に出す
選考オペレーション 打ち切りをやめた（カードの中で送れる）
特別選考・通常選考 500 → 2000
```

★ 件数を数える問い合わせを別に投げていない ―― 一覧と件数で**2つの答えが
ずれる瞬間**ができる。1件多く取れば「切ったか」は確実に分かる。

検証: 本番のデータで 人を探す 513 行・通常選考 294 行・特別選考 294 行・
候補者追加の表 297 行（打ち切りの札は出ていない）。
