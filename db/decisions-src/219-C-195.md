## C-195 APIキーはALL権限の画面で暗号化保存し、持続利用する

依頼者の指示（実行⑱）――APIキーを貼れる場所を作る。

ALL権限だけが開ける `/ai` を追加した。当初はAPIキーを毎回貼る作りにしたが、
依頼者から「持続的に使え」と訂正を受け、0048で暗号化保存へ改めた。
APIキーは `YOUTHDB_SESSION_SECRET` から用途別に導いた鍵でAES-256-GCM暗号化し、
DBには暗号文・IV・認証タグだけを置く。復号値は画面・Cookie・URL・Gitへ返さず、
登録後のAI分析でサーバが自動的に再利用する。氏名・メール・電話は送らず、
応募フォーム本文だけを1件ずつ分析する。分析結果は従来どおり
`ai_pre_assessments` に追記し、成績の `evaluation_scores` には入れない。

AI分析を左の操作柱へ独立したボタンとして置く案は依頼者が退けた。入口は
ALL権限の「通常選考 → 書類選考 → 採点」の中だけに置き、パンくずも
「通常選考 / 書類選考 / 採点 / AI分析」とする。採点中の候補者IDを持ち回り、
別の候補者を待ち行列の先頭から勝手に分析しない。

CLIの環境変数経路も残す。API障害や認証失敗の本文を画面へ流さず、固定した結果
コードだけを戻す。セッション秘密を変えると以前の暗号文は復号できないため、
変更後は画面からAPIキーを再登録する。

検証: `tests/37_session.test.ts`（ALL限定）、`tests/70_ai_pre_assessment.test.ts`
（待ち行列に個人識別列を含めない、分析済み除外、暗号化保存と復号）。
