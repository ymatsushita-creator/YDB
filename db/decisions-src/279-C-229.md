## C-229 実データを NEO の外へ移し、受け入れ口の既定値を廃止した

依頼者が実データを NEO の隣から外へ移した（R2 の是正）。その副作用を塞いだ。

#### 移動そのものが穴を開けていた

★★ **`.claude/settings.json` の deny が、新しい場所を覆っていなかった。** ★★

```
"Read(../YouthDB-private/**)"    ← 旧パス基準。移動先には効かない
```

実在候補者の顔写真・応募書類・legacy DB dump が、**実装セッションのAIから読める状態**に
なっていた。移動は R2 を是正したが、**同時に読み取りの防壁を外していた。**
相対パス1本に守りを預けていたので、置き場が動いた瞬間に無効化された。

塞いだ ―― 絶対パス・`../../`・`**/YouthDB-private/**`・`**/お顔データ/**` を deny に足した。
★ **パターンで書く。** `.env.localecho` が完全一致の ignore を素通りしたのと同じ形である。

#### 既定値を廃止した

`intakeDir()` は `<リポジトリ>/../YouthDB-private` を既定にしていた。
移動によって**その既定は存在しない場所を指すようになった。**

★★ 「存在しないから安全」は成り立たない。 ★★
**将来そのパスに誰かがディレクトリを作れば、intake は黙ってそこを使う。**
設定を1つ忘れたまま動いてしまう ―― `.env.localecho` と同じ構造である。

`YOUTHDB_INTAKE_DIR` を**必須**にした。未設定の実行は、見当違いの場所を掴むのではなく
**止まる。** 実在候補者の控えを書く先を、既定値に推測させない。

#### 所在を追跡下の文書に書かない

旧パスを指していた8箇所を直したが、**新しいパスを書き写さなかった。**

★ 書けば**リポジトリが個人情報の所在を指す索引になる。** 追跡下の文書
（`README.md` / `CLAUDE.md` / `.gitignore` / `.env.example` / `Hitler.md` §0 /
`investigator.md`）はすべて「`YOUTHDB_INTAKE_DIR` が指す」という書き方にした。
実際の値は各自の `.env.local`（追跡外）に置く。

`scripts/check-structure.ts` の S6 も同様に直した ―― 正の対照が実データの置き場を
指していたので、`__intake_probe__` という無関係な名前に変えた。
**検査が見るのは「外なら受理するか」だけで、置き場を知る必要が無い。**

#### R2 は充足していない

移動先は NEO の外だが、**同じ物理ディスク上である。**
R2 の条文は「別ボリューム、または暗号化ディスクへ」であり、
ディスクごと持ち出されれば一緒に出る。**`Hitler.md` §0 に未充足として記録した。**
`.dictator/check.mjs` が緑になったのは、R2 が NEO 直下しか見ていないためである。
★ **検査が緑であることを、条文を満たした証拠として使わない。**

#### 併せて

移動先に `Hitler.md` が混じっていた（原本＋「プロジェクト名: YouthDB-private」の1行）。
**データ置き場はリポジトリではない**ので削除した。
