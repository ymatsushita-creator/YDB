### C-28. 実年度と創作のデモを同じ DB に置けなくした

実行⑦。**実データの受領で初めて表に出た衝突である。**

D-8 の追記で本番のシードに 2026年度を入れたところ、`pnpm test` が落ちた。
`src/seed/demo.ts` は 2024〜2027 の4年度を創作しており、**2026 が重なる。**
`seasons_year_key`（`enrollment_year` の UNIQUE）で衝突した。

#### 衝突そのものより、衝突を避けたときのほうが危ない

素直な直し方は、デモ側を「既にある年度は作らない」にすることだった。
**これは採らない。** 衝突しなくなる代わりに、**創作の応募・評価・判定が
実在する 2026年度にぶら下がる。** 画面の数字が実在の年度の名前で嘘をつく。

止まって落ちるほうがましである。**辻褄が合っている＝正しい、ではない**
（実行⑥で踏んだ「丸め込みが欠陥そのものを隠す」と同じ形）。

デモ側の年度をずらす案も採らない。ずらしても**次の実年度（2027）で同じことが
起きる。** 年度をずらすのは、衝突の時期を先送りするだけである。

#### 直し方 ―― 環境ごとに入るシードを分けた

`*.example.sql` が「サンプルの環境にだけ入る」という仕組みは既にあった。
その逆向きを足した。

```
0001_reference.sql              どちらの環境にも入る（辞退理由など）
*.example.sql                   サンプルの環境にだけ入る
*.production.sql                本番の環境にだけ入る  ← 追加
```

実在する年度は `db/seeds/0002_season_2026.production.sql` に置く。
判定は `src/db/migrate.ts` の `loadSeeds`。1行の分岐で、
`includeExamples` のときに `.production.sql` を外す。

```
pnpm db:reset   サンプル＋デモ。実年度は入らない
seed(db)        本番。実年度が入る。デモは入らない
```

**「サンプルを入れる」と言った環境に、実在の記録を入れない。**
この規則は年度に限らない。実データを取り込む段（`DATA-INTAKE.md` 3節の 4）でも
同じ境界を使う。

固定しているテストは `tests/22_reference_season.test.ts` の
「実年度と創作のデモは同居しない（C-28）」3件 ――
サンプルの環境に年度が0件であること、デモを入れると 2024〜2027 の4件になること、
本番の環境にサンプルのチャネルが入らないこと。
