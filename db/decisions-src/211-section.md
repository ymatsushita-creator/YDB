### C-160. 評価軸に「何を見るか」を持たせる（依頼者の指示）

依頼者の言葉（実行⑯）――「評価軸や選考関係はもっと情報を取得して、DBに組み込んで」。

#### 手元の写しに、まだ読んでいないシートがあった

シート一覧を数え直したら、実行⑫が読んでいたのは**3枚だけ**だった。
選考に関わる文面はここにあった ――

```
特別選考        9軸それぞれの**判断の観点**が3〜13行ずつ
013_選考フロー   段ごとに事務局が何をするか（特別選考フロー／通常選考フロー）
募集要項        応募条件（年齢・コミット時間・理念への共感）
```

★★ **DB には軸の名前しか入っていなかった。** ★★
「NEOの環境を“使い倒せる”時間と覚悟」という名前だけが画面に出て、
**何に対して4点なのかは、採点する人の頭の中にしか無かった。**

#### 入れたもの（0042）

```
evaluation_criteria.description   軸の観点        18本（2期・3期）
selection_steps.description       段の手順        10段
season_requirements               募集要項 9条 × 2期
```

★ 列を足すだけにする。既存の行は動かさない（適用済みは編集しない）。
★ 募集要項は**期の条件**なので、段にも軸にもぶら下げない。
  `seasons` に列を足すと1行の自由文になり、条文ごとに読めない ―― 行で持つ。
★ 2期の要項を3期にも入れた（C-152 と同じ扱い。依頼者「変わらないので引き継げ」）。

#### 読み方で気をつけたこと

★ **見出しが0列目にあるとは限らない。** 表は列をずらして書かれている ――
  0列目だけを見ていたときは9軸すべてを取りこぼした（**実測0本**）。
  先頭の非空セルを見出しとして扱う。
★ **日付・担当者名を説明として拾わない。** 「。」で終わる12文字以上の文だけ。
★ **PJT の設計表は募集要項ではない。** 枠数やチーム構成は条件ではないので採らない。
★ **要約しない。** 運営が書いた文をそのまま入れる。採点者が読むのはその文である。
★ 入っている説明は**上書きしない。** 画面から直した文を表の古い文で潰さない。

#### 出す場所 ―― 点を付けるところ

`app/_components/scoring.tsx` の軸の下に、観点をそのまま出す。
**畳まない** ―― 開く操作を挟むと読まれず、結局は名前だけで点が付く。

検証: `tests/67_selection_detail.test.ts` 11件（見出しが0列目に無くても読む／
観点が空の軸は返さない／軸名を作り変えない／日付や担当者名を拾わない／
同じ条文は2度入らない／**点を付ける画面に観点が出る**）。
