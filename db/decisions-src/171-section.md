### C-120. 保留していた3つを決めた（依頼者が判断を委ねた）

依頼者の指示（実行⑬）――「君が判断して良い。信じて続けろ」。
C-119 で「置き場所を決める必要がある」として残した3つに答えを出した。

#### ★ 2つは**足さなかった** ―― 既存の記録層で表せる

```
AWARDへの応募有無     イベントへの参加は**接点（touchpoints）**である。
                      0028 で同じ問いに答えが出ている ――「参加という事実を人に貼る
                      場所はすでにある。新しい属性の列を作ると、同じ事実が2箇所に載る」
関連するアカデミア生   `touchpoints` は `person_id` と `partner_id` の両方を持つので、
                      **その団体経由で接点のある人**として既に導出できる
                      （`/approach` の「識別（人）」がそれを数えている）。
                      氏名の文字列で人を指す列を作らない
```

★ **列を足すことは、答えを出すことではない。** 表に列があるからDBにも列が要る、
とは限らない ―― 同じ事実が2箇所に載れば、必ずどちらかが古くなる。

#### 推薦枠ステイタスだけ足した（0035）

**これだけが置き場所を持たなかった。** 「**2期生**推薦枠ステイタス」は期の言葉で、
`partners` の現在値にすると 3期を入れた瞬間に 2期が消える。

形は 0016（アプローチ状態）と同じにした ―― マスタ＋追記専用の出来事＋最新から導く現在値。
同じ性質のものに別の形を与えない（次に触る人が2つの規則を覚えることになる）。
値は運営の語のまま（未連絡／メール送信済み／アポ実施済み／対象外）。

実測（デモ）――2期で「アポ実施済み」を保存して「1件を直した」。**3期へ切り替えると
推薦枠は空**で、担当部署・社内担当（団体の属性）はそのまま残る。**期ごとと団体ごとが
画面の上で分かれている**ことを確かめた。

★ 訂正の意味を取り違えて、テストを1つ間違えて書いた。打ち消し行は
「無かったことにする」のではなく「**こう直す**」であり、訂正行が持つ値が新しい現在値になる
（0016 と同じ）。実装ではなく**こちらの理解のほうが間違っていた。**

#### `/pilot` は**消さずに繋いだ**

C-119 で見つけた孤立。画面自身が「手順が終わったら消してよい」と書いているが、
**Pilot は HOLD のままで手順はまだ走っていない** ―― 消すのは観測を取るための足場を
先に捨てることになる。画面が「通常選考 › 試運転」と名乗っていたので、
**名乗った親（`/borderline`）から入れるようにした。**
`tests/49` の期待値が `['/pilot']` から `[]` になった ―― 孤立は0件。

#### 残るフォームは**そのままにした**（判断の記録）

```
/approach/new       団体の新規作成。写真と最初の接触を伴う。**1件の作成であって
                    羅列ではない**。まとめて直す道は「団体を直す」の表が持っている
/people/{id}/edit   1人の詳細（写真つき）。**まとめて直す道は `/people/new` の表が持つ**
                    ―― 同じことを2つの形で作らない

```

★ 「フォームをすべて表にする」ことが目的ではない。**まとめて打つものが表で、
1件を開いて直すものがフォームである。** 表にする理由が無いものを表にすると、
1件を直すのに表を探すことになる。
