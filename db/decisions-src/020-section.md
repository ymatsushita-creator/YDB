### A-19. 「根拠は必須」が、空白の種類によって破れていた

実行⑥。E2（点と根拠を画面から保存する）を作り、空の根拠が弾かれることを
テストで確かめようとしたら、**改行だけの根拠が保存できた。**

原因は `btrim` の既定値である。

```sql
btrim(rationale) <> ''      -- 既定は btrim(rationale, ' ')。半角スペースだけ
```

通っていたのは次の形である。

| 入力 | 当時 |
|---|---|
| `''`（空文字） | 弾かれる |
| `'   '`（半角スペース） | 弾かれる |
| 改行だけ / タブだけ | **通る** |
| 全角スペースだけ | **通る** |

原典のコメントはこう書いている ――「空文字が通ると『必須にした』という
設計意図が形骸化する（資料5-3）」。**意図は正しく、実装が届いていなかった。**
B 節の表に「`rationale` が空白のみは不可」と書いてあるのに、
実際には空白のみで通る形が3つあった。

**これは「記録が実装より厳密に見える」形である。** 読んだ人は守られていると
思って確認をやめる。DECISIONS.md の冒頭がいちばん警戒している壊れ方で、
B 節の表そのものが一度それで破れている。

**表に出なかった理由。** 画面から入力できなかったので、根拠は
デモの生成コードとテストからしか入らず、どちらも実文を入れていた。
**入力欄を作った瞬間に踏める穴になった。**

**対応**（0015）: 落とす文字を明示した。

```sql
CHECK (btrim(rationale, E' \t\n\r　') <> '')
```

0001 は適用済みなので編集せず、制約を落として付け替えた。2つ残すと
どちらが効いているかが読んで分からない。既存の行が違反しないことは
`pnpm db:reset` と全テストで確かめた（デモの根拠はすべて実文）。

画面（`required` 属性）で弾く形にはしなかった。**判定を記録層に1つだけ置く。**
実際に `required` を外して全角スペースを送り、`rationale_blank` が返ることを
実データで確かめている。

→ `tests/20_score.test.ts`「根拠が空だと拒否される（空白・改行・タブ・全角スペースも）」
→ `tests/20_score.test.ts`「前後に空白があっても、中身があれば保存できる」
