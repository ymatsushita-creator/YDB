0035 の直後の連番で参照データが入っている以上、走ったのは
**migrate と seed を両方やる `db:migrate:production` そのもの**である。

否定できた経路 ―― CI は無い（`.github` が存在しない）。`migrate()` の呼び出しは
4箇所しか無く（`testing.ts` / `server.ts` はどちらも PGlite、`db-reset` は
`DATABASE_URL` があれば拒否、残りは上記2つ）、**アプリの実行経路と
`next build` からは呼べない。** Vercel は `VERCEL=1` でデモ（PGlite インメモリ）。

★ **穴は「意図しない経路」ではなく、こちらが渡した塊だった。**
実行できる形で本番への書き込みを渡した時点で、それは自分が流したのと同じである。

## 2. 3期を2期にそろえた ―― 保留を解いたのは依頼者

### 確かめてから動かした

C-55 は3期について**受け取った語のまま**置き、2期との違い（段が1本少ない・
1本目が「書類審査」）を黙って揃えなかった。実行⑭で依頼者に確かめた。

| 問い | 依頼者の答え |
|---|---|
| 「書類審査」は2期の「書類選考」と同じ関門か | **同じ。「書類選考」に揃える** |
| 3期に「応募受付」を足すか | **足す。2期と同じ5段** |
| 2期の軸をどこまで写すか | **特別選考の重み付けも、最終面接6軸も写す** |

★ 受領した語を勝手に翻訳しないのが規律であり、**確認したら直す**のも同じ規律である。
★ **保留を解けるのは依頼者だけである。**

### 形は2期から読む

`db/seeds/0006_season3_align_to_season2.production.sql` は、段も軸も
**2期の行を SELECT して写す。** 同じ語を2枚のシードに書けば、片方を直したときに
もう片方が古くなる。位置の入れ替えは 0005 と同じ技法（+100 へ逃がして詰め直す）。

```
3期（前）  特別選考(1・9軸/重みなし) 書類審査(2) グループ面接(3) 最終面接(4・軸0)
3期（後）  特別選考(1・9軸/必須3・加点6) 応募受付(2) 書類選考(3)
           グループ面接(4) 最終面接(5・6軸)
```

★ 3期の特別選考9軸は、実行⑫の取り込み（C-105）が**本番へ直接**入れており
**シードには無かった。** 本番にあってシードに無い形は、次に DB を作る誰かの前で
静かに消える。0006 がその差も埋めた。

### 流す前に、流す先の形で確かめた

新しい DB でシードを順に流した姿（`tests/22`）と、**本番の姿**（取り込み済み・
呼び名が違う・重みなし）は別物である。後者を作り直して 0006 を当てる検査を
`tests/52` に置いた ―― 収束すること、軸が重なって増えないこと、
**応募が乗っている期は並べ替えないこと**（C-105 と同じ条件）。

### 期をまたいで壊れたテストが、また出た

`tests/22` の「最終面接に6軸」「満点の合計は24」は**期で絞っていなかった。**
3期にも同じ6軸が入った途端に12軸・48点になる。
**「1件しかない」を前提にしない** ―― C-54 から3度目である。
