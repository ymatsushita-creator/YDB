## 2. 表（スプシ形式）―― `'use client'` が0件でなくなった

実行⑪まで、こちらの書いた画面は素の `<form action={...}>` だけで動いていた。
依頼者の指示は「1行＝1件、追加も表の上で、まとめて保存、スプシから貼り付け」。
**行を1つ増やすたびに打った値が消える形では、その体験は作れない。**

増やしたのは `app/_components/sheet.tsx` の1つだけで、
`tests/45_home.test.ts` が**これ以外に増えていないこと**を見張る。

**判定は1つも持たせていない。** 表が持つのは行の状態（値・新規か既存か・失敗の理由）で、
保存は既存のコマンドを行ごとに呼ぶ。**入口が増えても規則は1つ**（C-59 と同じ扱い）。

### 置き場所

```
人・接点・アプローチ状態  候補者追加（/people/new）を表にする。既存行も同じ表に並ぶ
団体の属性                団体アプローチ（/approach）の3つ目のタブ「団体を直す」
接触の記録                団体の行を開いた先
```

### ★ 画面に出す母集団を間違えた

表の既存行を `candidate_numbers`（期ごとの候補者番号）だけから引いていた。
デモの2期で開くと**既存行が1件も出なかった** ―― 番号は実行⑩で足した仕組みで、
それ以前の記録は持っていない。本番の取り込み分（61人）は番号を持つので、
**本番だけ動いて見えるところだった。**

アプローチ状態が記録されている人も母集団に入れ、番号を持たない人は後ろへ回した。
`tests/41` に「番号が無くても表に出て、直せる」を固定した。

### ★ 保存できた行に ID と番号を貼る

貼らずにもう一度保存すると**同じ人が2件できる。** 画面で実際に2回押して確かめた。
候補者番号は保存で確定する（出した番号を予約しない。C-79）ので、番号も返して貼る。

### 表に出さない列を、空で消さない

更新は全列を書くので、表に出していない紹介者を空で渡すと**黙って消える。**
現在値を読んでそのまま渡している。

### 落ちた理由を、表の外にも出した

結果の列は右端にある。列の多い表では横に送らないと読めないので、
表の下に「n 行目 ―― 理由」を並べた。**切れて見えるものは読めないのと同じ**（C-65）。

## 7. リキッドグラス（追加の指示。仕様書を受領）

依頼者から仕様書（`liquid-glass-pc-spec.md`）が届き、「ボタンUIはこれで直して」。
**この製品と正面から衝突する3点を挙げ、選んでもらった** ―― 範囲は浮いているものだけ、
背景は敷かない（意匠規定を守る）、追従光は入れる。

`app/glass.css` を4枚目の層として足した。**外せば物理ボタン（実行⑨）に戻る。**

### 仕様書どおりにしていない3点

★ **① 単色の面の上では `backdrop-filter` を使わない。** 操作柱と帯は真っ黒で、
背後に情報が無い。ぼかしても何も変わらずコストだけ掛かる（仕様 §9 の禁止事項）。
ぼかすのはポップアップの器だけ ―― 実測で**同時可視1枚**（予算は3枚）。

★ **② `prefers-color-scheme` で切り替えない。** この製品の明暗は**面で決まる**
（操作柱は常に黒、カードは常に白）。OSの設定で白いカードを暗色にすると、
黒い文字が読めなくなる。

★ **③ 白い地の上に載るものは、ティントを別に決める。**

### ★ コントラストを2回落とした（どちらも実測で見つけた）

```
主ボタン        暗いティント .55 を白いカードの上で使い、白文字が 3.83（要 4.5）
                → 必要な濃さを計算して .78 に。9.17
ポップアップの器 背後が暗いとき 3.02（仕様 §8 の「最明・最暗の両方で AA」に反する）
                → .72 に上げた。8.2。**濃くしてもぼかしは見える**
```

★ **私の検査器も間違っていた。** 半透明の面を「不透明な祖先の背景」と比べていたので、
**ガラスの上の文字を測ったことになっていなかった**（0件と出た）。
半透明は**重ねて**測る。**数えた結果を疑う前に、数え方を疑う。**

### ★★ ビルドが、プレフィックス無しの `backdrop-filter` を消していた

仕様書 §4 は `-webkit-` 側から `brightness()` を落とした例を載せている。
そのまま書いたら **Lightning CSS がプレフィックス無しのほうを消し、`-webkit-` だけを
残した** ―― Chromium でぼかしが1枚も効いていなかった。
画面で「ぼかしを持つ要素 0 件」と出て初めて気づいた。
**同じ値を、プレフィックス付き → 無しの順で並べる。** テストで値の一致を見張る。

### `'use client'` が2つになった

`app/_components/glass.tsx` は**ポインタの座標を CSS 変数へ書くだけ**（光は CSS が描く）。
リスナは委譲で1つ。`CLAUDE.md` の規律を「表と追従光の2つだけ」に改めた。

```
pnpm test              546 件 全通過（536 → +10）
切れ 0 ・ 混色で測ったコントラスト不足 0 ・ ぼかし同時可視 1 枚
corner-shape: squircle が効いている ・ 追従光は1要素だけに入り離れると消える
```
