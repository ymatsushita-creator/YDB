## 6. Pilot Deployment Readiness（実測）

「URL から安全に試運転できるか」を測った。**実装はしていない。**

### 満たしている

本番ビルドが通る（1.4秒）／全ルートが動的でビルド時に DB を読まない／
`'use client'` 0件／マイグレーションのチェックサム検証／書き込みの母集団が
画面と揃っている／氏名と id を URL に入れない／実データが git に入らない／
`Db` 抽象が3メソッドで差し替え口が閉じている。

### ブロッカー

| # | 内容 |
|---|---|
| **B-1** ★ | **データが保存されない。** PGlite はローカル FS に書く。サーバレスでは運営の入力が消えるか他の人に見えない |
| **B-2** ★ | **認証が無い。** URL を知っていれば実在候補者の氏名を読め、判定まで書ける |
| **B-3** ★ | **`db:reset` に安全装置が無い。** 確認も環境判定もなく `rm -rf`。開発中に実際に2回壊している |
| **B-4** | **バックアップが無い。** B-3 が起きたら戻せない |
| B-5 | 実データがまだ無い（既知） |

### 実装順（デプロイ先が決まってから）

**1. `db:reset` の事故防止 → 2. バックアップと復元 → 3. 認証 → 4. DB の分離 →
5. マイグレーション手順 → 6. エラー確認 → 7. 公開環境の E2E**

**1と2を認証より先にする。** 消えたデータは戻らないが、バックアップがあれば
認証の穴は「読まれた」で済む ―― **可逆性が違う。**
