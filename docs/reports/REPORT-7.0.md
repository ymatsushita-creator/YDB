## What Changed

### 1. 実データを受け取り、読んで、止まった

旧 NEO-Youth の Supabase から全10テーブルを受領（`db/private/`、SHA-256 一致）。
**中身を読む前に除外規則をコミットした** ―― 規則自体が未コミットで、
次のコミットで氏名が2リモートへ公開される状態だった。

`DATA-INTAKE.md` の手順どおり **2（列と行を読んで報告する）で止めた。**
列の意味をこちらで推測すると、根拠のない対応付けが記録に入る。

### 2. 回答を受けて、本番のシードに入れた（D-8 の保留を解いた）

2026年度・選考ステップ4件・評価の観点6件。**確定と推測を分けて記録した。**

推測は1列だけである ―― `application_close_date`（2026-03-22）。
締切は DB にもコードにも無く、実績の最終応募日を締切と見なしている。
判明したら `season_revisions` に履歴を残して直す。

**旧システムの8つの遷移のうち、段は4つだけ**と判断した。
合格・補欠合格・辞退・保留・承諾書提出は結果か状態であって段ではない。
段に混ぜると「最終ステップを通過したら合格」が壊れる。

**書類選考の軸は入れていない。** 満点16は確定しているが呼び名が無い。
名付けると運営が使っていない語がマスタとして固定化する（原則3）。

### 3. 実データの受領で、隠れていた衝突が1つ表に出た（C-28）

デモが 2024〜2027 を創作しており、**実在する 2026 と重なった。**

衝突を避ける素直な直し方（デモ側で「既にある年度は作らない」）は**採らなかった。**
衝突しなくなる代わりに、**創作の応募が実在する年度にぶら下がる。**
画面の数字が実在の年度の名前で嘘をつく。止まって落ちるほうがましである。

`*.production.sql` を足し、サンプルを入れる環境から実年度を外した。

### 4. ロゴとパレットを NEO ACADEMIA ブランドにした（C-29）

**保留していた生成元が、依頼者の指示で決まった。**
色は規定に書かれた値をそのまま置いている（ロゴ画像から吸っていない）。

最重要原則「色は線、面は黒」を**トークンの側で強制した** ――
面に使われるトークンを全部白か黒に倒したので、
**アクセント色の面塗りが構造的に作れない。**

色を消した結果、やることの種別が全部黒文字になって一覧が読めなくなった。
**色は消すのではなく面から線へ移すのが規定の意図**なので、
バッジを左の2px 線へ組み替えた。

### 5. 公開して見せられるようにした（C-30）

```
https://ydb-ten.vercel.app
```

サーバレスには書き込めるディスクが無く、`.pgdata/` も配られない。
**永続を諦めて、起動のたびに使い捨ての DB を組み立てる。**

**これは Pilot の本番ではない。** 画面の右上に
「デモ ・ 架空データ ・ 保存されません」と赤字で出している ――
URL を渡された人には、それが実データかどうかを確かめる手段が無い。

### 6. 面接官の目で言葉を読み直した（C-32）

3人の採点官のつもりで文言を全部読み、**内部の語が9か所そのまま出ていた**のを直した
（`pending の評価` / `jst_today() - jst_date(assigned_at)` / 停止理由 / 窓の内側 ほか）。

**1つだけ直さなかった。** 「Community」を「林」と訳さない ――
実装の林は**人**、Community は**組織**である。訳すと同じ語が2つの意味を持つ。
画面では「連携先」と書いた。**食い違いを勝手に寄せない**（D-11 が決まるまで）。

## Operator Value

**運営にとって増えた価値は、正直に言えば小さい。**

増えたのは「見せられること」と「言葉が読めること」であって、
**できる仕事が増えたわけではない。** 実データはまだ1件も入っていない。

- URL を渡せば、運営でも社長でも**自分の手で触れる**（架空データ）
- 画面から DB の状態名や関数名が消え、**面接官が読める日本語になった**
- 実運用に何が足りないかが**12件の具体的な依頼**になった（推測ではなく、
  実際に詰まった場所）

## Validation Report

### 誰が検証したか

**開発者だけである。運営は誰も触っていない。**
したがって以下はすべて **Developer Hypothesis** であり、

### 実データで確認した内容

**実データでは1周していない。** 確認したのは次の2つ。

| 何を | どうやって | 結果 |
|---|---|---|
| 実データの中身 | 全10テーブルの列と行を機械的に集計。SHA-256 で完全性を確認 | 61名・32名・変更履歴410行。`step_history` は0行 |
| 本番シードの値 | `tests/22_reference_season.test.ts`（15件） | 値だけでなく**入っていないこと**も検査。3か所をわざと壊して7件落ちることを確認 |

### 架空データで確認した内容

**実データが入らないので、架空データで代替した。** 母集団だけは本番に寄せた ――
デモの年度ではなく**実在する2026年度（4ステップ・6軸）**で回している。

**10通りの回し方**（素通り／不合格／担当未割当で採点／保留と解除／利益相反／
判定の訂正／点の二重入力／担当変更／10人同時／辞退と個人情報削除）。
**進めなかった場所は0件。**

**架空の10人を3回通した。3回とも完全に同じ結果になった。**

```
木 10 / 幹 7 / 辞退 1 / 動いている 0 / やること 0 / 遷移 33 / 点 42
```

照合したのは、数えた結果と事実が合っているか ――
やることの二重計上0、根拠が空の点0、不合格のステップが「書類選考」2件、
最後に「動いている応募」と「やること」が両方0になること。

### 未検証のケース

- **実データでの1周**（生年月日が無いため1人も入らない）
- **日をまたぐ挙動。** 滞留と SLA は同日の検証では現れない。
  `step_history` が0行だったため、**移行データでも代替できないことが確定した**
- **公開環境での書き込み。** デモモードは判定を押せるが保存されない
- **運営の操作。** 誰も触っていない

### 今後確認すべきケース

- 軸が0本のステップを通したときに、運営が「点を入れ忘れた」と気づけるか
- 「連携先」という語が運営に通じるか（こちらが作った第3の語である）
- 保留にできないことに、運営が実務で詰まるか

## Technical Debt

- **色に対する自動テストが無い。** 「アクセント色が背景に使われていない」の検査は
  CSS の静的解析になり、いまの `node:test` の枠から外れる
- **10周と10人×3回は使い捨ての脚本で、リポジトリに残していない。**
  残すなら「軸が0本のステップを確定できてしまう」を先にテストへ書く順序になる
- **`getCommunityMap` にテストが無い**（FusionAI の PR で入った新しい集計）
- デモモードのコールドスタートが約12秒（温まれば2秒台）

## Risks

- **リポジトリは public である。** 実データは `db/private/` にあり追跡下に無いが、
  規律が1度でも破られれば取り消せない。コミットのたびに確認している
- **公開 URL に認証が無い。** 架空データなので実害は無いが、
  **実データを載せる段でこの経路は使えない**
- **推測値が1つ本番のシードに入っている**（応募締切）。
  由来は D-8 に残したが、読み飛ばされれば確定値として扱われる

## Recommendation

**Option A —— 実データを入れる（推奨）**

不足している5件（生年月日・メール・学校・職員名簿・応募日時）を受け取り、
`db/private/` から `.pgdata/` へ取り込む。**生年月日が最大の障害**で、
旧 DB に無い以上、①改めて集める ②`birth_date` を NULL 可にする、のどちらか。
**②は記録層の変更なので、判断を仰ぐ。**

実データで1周できれば **Go 条件1が満たせる。**

**Option B —— 観測を先にやる**

実データを待たず、架空データのまま運営4名に触ってもらう。
**Validated Operator Problem が0件のまま**という状態を先に崩す。
数字の妥当性は訊けない（架空だから）が、
**操作の流れ・迷う場所・言葉の食い違い**は取れる（`CHECKLIST.md` 0-1-1）。

**私の推奨は B である。** 実装量あたりの学習量が最大になる。
A は依頼者と社長の作業待ちで、こちらからは動かせない。
B は日程さえ決まれば今日の状態で実施でき、**観測0件という最大のブロッカーに直接効く。**
