## 1. 社長に確認したいこと（4問）

### 1-1. 年度の名称と、定めた4つの日付

`seasons` は4つの日付を持ち、**集客開始 ≤ 応募開始 ≤ 応募締切 ≤ 選考終了**の
順序を満たす必要がある（`DATA-INTAKE.md` 4節）。

**実データにこの4つは記録されていない。** 上の「読み取れた時期」は実績であり、
「3月10日から受け付けると決めた」のか「たまたま最初の応募が3月10日だった」のかは
区別できない。**この差は充足率と滞留の分母を変える。**

- 年度の名称は何か（例: 2026年度／1期／2期 など、実際に使っている呼び方）
- 集客開始・応募開始・応募締切・選考終了の4つの日付
- `youth_partnerships` の活動が7月末まで続いているが、**これは次年度の集客か**

> 定員36・目標応募数100は受領済み（D-8）。ここでは訊かない。

### 1-2. 選考ステップの正式な並び

**`youth_candidates.step` は61行すべて `未観測` で、ステップが記録されていない。**

`status` 列には次の8種が入っている（件数順）。

```
合格 32 / 書類選考 7 / 辞退 7 / 応募前 7 / 補欠合格 4 / 保留 2 /
グループ面接 1 / 最終面接 1
```

**これは段階と結果が1列に混ざっている。** 「書類選考」「グループ面接」「最終面接」は
ステップに見え、「合格」「補欠合格」「辞退」「保留」は結果や状態に見える。
**こちらで切り分けると、根拠のない対応付けが記録に入る**（`DATA-INTAKE.md` 3節、
Pilot Rule「運営の言葉をこちらの語に翻訳して記録しない」）。

- 選考のステップは、実際には何段階で、どういう順番か
