## 1. いちばん重要な約束

> ### 実データを `db/seeds/` に置かない。
>
> `db/seeds/*.sql` は **git の追跡下**にあり、
> **GitHub の2つのリモート（origin / mirror）へ push される。**
> 候補者や職員の氏名・メールを置くと、**そのまま公開される。**

置いてよい場所は次のとおり。

| 置き場所 | git | 何を置くか |
|---|---|---|
| `db/private/` | **除外**（この文書と同時に `.gitignore` へ追加） | **受け取った実データそのもの。**候補者・職員を含む |
| `.pgdata/` | 除外（既存） | 取り込んだ後のデータベース実体 |
| `db/seeds/0001_reference.sql` | **追跡** | **個人を含まないマスタのみ**（年度・選考ステップ・評価の観点） |

**判断に迷う列があれば、`db/private/` に置く。** 迷ったら公開しない側に倒す。

---

## 2. 送っていただきたい形

**どの形でも受け取れる。** 加工は不要で、**エクスポートしたそのまま**でよい。

- スプレッドシート（`.xlsx` / `.csv`）
- データベースのダンプ（`.sql` / `.db` / `.sqlite`）
- Notion / kintone / Airtable の書き出し
- 画面のスクリーンショット（列名が読めれば可）

**受け渡しは GitHub 以外の経路で。** チャット添付、共有ドライブ、
USB のいずれでも構わない。**このリポジトリに直接コミットしない。**

### 一緒に教えていただきたいこと（2つだけ）

1. **いま選考が動いている年度はどれか**（複数年度が入っている場合）
2. **そのファイルに実在の個人情報が含まれるか**（はい／いいえ）

---

## 3. 受け取ったあとの手順

```
1. db/private/ に置く（git に入らない）
2. 列と行を読み、何が入っているかを一覧にして報告する
   ―― この時点では取り込まない。中身を勝手に解釈しない
3. 個人を含まないマスタ（年度・ステップ・評価の観点）だけを
   db/seeds/0001_reference.sql に最小の変更で追加する
4. 候補者・職員は db/private/ から .pgdata/ へ取り込む
   （git に残らない経路）
5. 実データで採用の1周を通す
6. Pilot の判定に進む
```

**2 で止まって報告する。** 列の意味をこちらで推測して埋めると、
根拠のない対応付けが記録に入る（`CLAUDE.md`「未確定の値を
たぶんこうだろうで埋めない」）。読み取れなかった列は
**読み取れなかったと報告する。**

---

## 4. 取り込みで守ること

- **日付は `jst_date()` を通す。** タイムゾーン依存の解釈をしない
- **4つの日付の順序**（集客開始 ≤ 応募開始 ≤ 応募締切 ≤ 選考終了）を満たさない
  行は取り込まず、そのまま報告する
- **評価の観点には満点が要る**（`scale_max` は NOT NULL）。
  元データに無ければ、**推測せず確認する**
- **氏名・メールをログや URL に出さない**（既存の規律。C-20）
- 取り込みは**やり直せる形**にする（`pnpm db:reset` で戻せること）

---

## 5. スクリーンショットと報告書について

**実データの氏名を、報告書・スクリーンショット・コミットメッセージに書かない**
（`CLAUDE.md` 9節）。Pilot の報告に載せるときは、
**架空の名前に置き換えるか、伏せる。**

観測シートに候補者名を書く必要は無い ―― 記録するのは
**運営の行動**であって、候補者が誰かではない。
