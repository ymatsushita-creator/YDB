# Pilot チェックリスト

**目的は「使えるか確かめる」ことではない。** 運営担当者から**最大限の学習**を
得ることである（`process.md` の Pilot Rule）。

> Pilot の目的は不具合ではなく**誤解**を見つけること。
> 運営が迷ったら、運営ではなく**画面が間違っている**と考える。

---

## 0. 実施前の準備（開発者・10分）

### 0-1. データ

**デモデータで行う。実データでは動かない。**

本番シード（`db/seeds/0001_reference.sql`）には `withdraw_reasons` しか入って
おらず、**年度・選考ステップ・評価軸が1行も無い**（`DECISIONS.md` D-8）。
本番データベースを開いても画面は空になる。

```bash
# 開発サーバを止めてから実行する（起動したままだと .pgdata が壊れる）
pnpm db:reset
pnpm dev            # ポート 3111
```

**この制約が学習に効く。** デモの氏名・団体名はすべて架空で、数字も創作である。
だから次の2つは**この Pilot では学習できない**。

- 数字が実感と合うか（母集団が架空なので、合わないのが当たり前）
- 実在の団体名・年度で読めるか

**代わりに学習できるのは「操作の流れ」と「言葉」である。** そこに集中する。

### 0-2. 記録の用意

`docs/pilot/OBSERVATION-SHEET.md` を対象者ごとに1枚コピーする。
**画面共有の録画があるとよい**（あとで迷いの秒数を数え直せる）。

### 0-3. 立ち会う人の約束（これがいちばん重要）

| やること | やってはいけないこと |
|---|---|
| 黙って見る | **操作を教える** |
| 手が止まったら**5秒待つ** | 「そこは○○を押します」と言う |
| 「いま何をしようとしていますか」と訊く | 「分かりますか？」と訊く（はい／いいえで終わる） |
| 相手の言葉をそのまま書く | こちらの語（森・林・木・Forest）に翻訳して書く |
| 「なるほど」で受ける | **画面を弁護する**（「本当は○○という意味で…」） |

**説明したくなったら、それが観測である。** 「説明が要る画面になっている」と
シートに書く。説明してしまうと、その観測は失われる。

## 1. 社長（15分）

**役割は操作者ではない。** 未決の判断と、方向の是非を答えてもらう。
データ入力はさせない（架空データに点を付けても学びが薄い）。

### やってもらう操作

| # | 操作 | 時間 |
|---|---|---|
| 1 | `/cockpit` を開いて、**声に出して読む**。「これは何の画面だと思うか」 | 3分 |
| 2 | 森のマップを見て、「気になる森はどれか、なぜか」 | 3分 |
| 3 | 応募1件（`/applications/...`）を開いて、履歴と評価を読む | 4分 |
| 4 | 未決の質問に答える（下記） | 5分 |

### 観察するポイント

- **最初に目が行くのはどこか**（4枚のタイル／マップ／やることの表）
- 「運転席」「森」「やること」を**説明なしで理解したか**
- 森のマップで**旗（滞留・休眠・接点なし）を根拠に選んだか**、
  それとも団体名の知識で選んだか
- 健康度（%）が無いことに**気づくか、不満を言うか**

### 聞く質問

1. この画面は、いま何を教えてくれていると思いますか
2. 明日の朝これを開くとしたら、**最初に見たいものは何ですか**
3. **年度の実数値**を教えてください（`seasons`。入学年・集客開始・応募開始・
   応募締切・選考終了・定員・目標応募数）。**これが無いと本番で使えません**
4. 合格者が**辞退**したとき、いま社内ではどこに記録していますか
5. 個人情報の削除依頼を受けた人の**過去の応募数**は、集計から消すべきですか
   （`DECISIONS.md` D-10。過去年度の数字が動きます）

### 成功条件

- [ ] 「これは何の画面か」を**こちらが説明する前に**言えた
- [ ] 質問3（年度の実数値）の答えが取れた ―― **本番投入の唯一のブロッカー**
- [ ] 質問4・5のどちらかに方針が出た
- [ ] 画面の言葉で**違和感を持った語**が1つ以上記録できた

## 2. 運営担当者（40分）

**本命。** ここでしか取れない観測が最も多い。

### やってもらう操作

`/pilot`（ナビの「試運転」）を開いてもらい、**手順は画面に任せる。**
こちらから読み上げない ―― 画面が手順を伝えられるかも観測対象である。

| # | 操作 | 時間 |
|---|---|---|
| 1 | `/cockpit` を開いて、**何も指示せず**「いつも通り仕事を始めてください」 | 5分 |
| 2 | 担当を決める（1件） | 5分 |
| 3 | 保留を解く（1件） | 5分 |
| 4 | 評価する（1件・軸すべて＋確定） | 12分 |
| 5 | 判定する → **わざと間違えて訂正する** | 8分 |
| 6 | 「今日の作業は終わりましたか？」と訊いて、判断を見る | 5分 |

**1 がいちばん重要である。** 何も指示しない5分で、**画面が次の一手を
伝えられるか**が分かる。ここで `/pilot` を開かず `/cockpit` から始めるのは、
実際の朝がそうであるため。

### 観察するポイント

| 場面 | 見るもの |
|---|---|
| 1 開いた直後 | **最初のクリックまでの秒数。**どこを最初に押したか |
| 2 担当を決める | 面接官を選ぶとき、**何を根拠にしたか**（待ち件数を見たか） |
| 3 保留を解く | 理由だけで判断したか。**ほかの画面を見に行ったか** |
| 4 評価する | 根拠を**何文字書いたか**。1軸ごとの再読み込みで**待ったか・ため息をついたか** |
| 4 確定 | 「確定」を押すのを**ためらったか** |
| 5 判定 | 押す前に**確認を探したか**（無いので探す動きが出る） |
| 5 訂正 | 訂正できると知って**安心したか、驚いたか** |
| 6 終わり | 「終わった」の判断を**何を見て決めたか** |

**迷いは秒で記録する。** 3秒以上のためらいは全部シートに書く。

### 聞く質問（操作の後にまとめて）

1. 手が完全に止まった場所はどこでしたか
2. **押せたけれど迷った場所**はどこでしたか（← これを必ず訊く。
   押せた場所は報告されないので、訊かないと消える）
3. 画面の外（メモ・チャット・表計算）に書きたくなったことはありましたか。
   **それを何と呼んでいますか**
4. いつもの仕事のうち、この画面に**出てこなかったもの**は何ですか
5. 合格者が辞退したとき、いまどこに記録していますか
6. この画面の言葉で、**社内で使っていない言い方**はありましたか

### 成功条件

**「全部できた」は成功条件ではない。**

- [ ] 手が止まった場所・迷った場所が**合わせて3件以上**記録できた
- [ ] 運営が使った言葉が**5語以上**そのまま記録できた
- [ ] こちらの語と食い違う言葉が**1語以上**見つかった
- [ ] 「画面の外に書きたくなったもの」が**1件以上**取れた
- [ ] 1周（担当→評価→確定→判定）を**こちらが操作を教えずに**通せた

**迷いが0件だった場合は、Pilot として失敗である。**
訊き方が誘導的だったか、立ち会いが助けすぎたかを疑う。

## 3. 初めて触る人（20分）

**誤解を見つける役。** 前提知識が無いので、こちらの言葉が通じるかが分かる。
運営経験は不要。社内の別部署の人でよい。

### やってもらう操作

| # | 操作 | 時間 |
|---|---|---|
| 1 | `/cockpit` を開いて、**声に出して読み上げる**（think aloud） | 5分 |
| 2 | 「この画面が言っていることを、人に説明してください」 | 5分 |
| 3 | 「いちばん急ぎだと思うものを1つ選んで、開いてください」 | 5分 |
| 4 | 語の意味を訊く（下記） | 5分 |

### 観察するポイント

- 読み上げで**つっかえた語**（そこが誤解の場所である）
- 4枚のタイルの数字を、**単位つきで読めたか**（件／人／森）
- 「いちばん急ぎ」を**期限で選んだか、上から選んだか**
- **森のマップを人の一覧だと思わなかったか**（森は組織である）

### 聞く質問

1. 「運転席」とは何だと思いますか
2. 「森」「林」とは何だと思いますか。**人ですか、組織ですか**
3. 「やること 26 件」と「待っている人 26 人」は**同じ意味ですか**
   （← 違う。件と人の区別が伝わっているかの試験）
4. 「滞留 2 件」「休眠 934 日」は何のことだと思いますか
5. どこを押せば何が起きると思いましたか。**外れた予想はありましたか**

### 成功条件

- [ ] 「運転席」を**説明なしで**それらしく言えた
- [ ] 森を**組織として**読めた（人だと思ったら、それは重要な観測）
- [ ] 質問3（件と人）で**違いに気づいた**か、気づかなかったかが判定できた
- [ ] つっかえた語が**3語以上**記録できた

## 4. 実施後（開発者・すぐ）

1. シートを埋め終える（記憶が消える前に。**当日中**）
2. 運営の言葉を**翻訳せずに**書き写せているか見直す
3. `docs/pilot/REVIEW.md` の手順でレビューする
4. `docs/pilot/REPORT-TEMPLATE.md` で報告書を書く
   （版は `REPORT-<実行番号>.<連番>.md`）

**この段階で実装を決めない。** レビューを通してから決める。
