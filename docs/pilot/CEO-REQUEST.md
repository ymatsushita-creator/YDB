## 補足（読まなくても回答できます）

### なぜこれが必要か

いまのシステムには**年度が1行も入っていません。** そのため本番のデータベースを
開いても画面が空になり、**実データでの試運転ができません。**

デモ用の架空データでは操作の流れは確かめられますが、
**画面に出る数字が実感と合うかは確かめられません**（人名も団体名も数字も
すべて創作のため）。Pilot を終える条件に「実データで1周」を入れているのは、
数字の妥当性を確かめないまま次の計画に進むと、
**あとで母集団の議論をやり直すことになる**からです。

### 未定の日付があっても構いません

「未定」と書いていただければ、その旨を記録に残して進めます。
**推測で埋めることはしません**（根拠のない日付が入ると、集客期間や
滞留日数の集計が静かに間違うため）。

ただし4つの日付は必須項目なので、**未定のものがあると年度を登録できません。**
その場合は「仮の日付で登録し、決まり次第差し替える」という扱いにしますので、
**仮でよいかどうかだけ**お知らせください。

### 期限（SLA）は今回聞いていません

「書類選考は何日以内に判断する」といった目安は、**後から足せる**設計に
なっています。今回は省いて、実データで動かすことを優先します。

### この回答で何が起きるか

1. 本番のシードに**年度・ステップ・評価の観点**を追加します（最小の変更）
2. 面接官の登録と候補者1名分の入力は、**GitHub に残らない形**で別途行います
3. 実データで採用の1周（担当を決める → 評価 → 確定 → 判定）を通します
4. そのうえで Pilot の判定（Go / Hold / No-Go）に進みます

**この回答が届くまで、Pilot の判定は Hold のままです。**
基準を緩めて Go にすることはしません。
