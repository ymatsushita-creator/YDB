# 履歴に残った API キーの対処 —— 2026-08-19

## 事実

`ANTHROPIC_API_KEY` が git 履歴に入っている。**作業ツリーには無い。履歴にだけ在る。**

```
0c9cd6e  fix: 画面を実際に触って見つけた崩れを直す（C-205 / C-206）   ← .env.localecho を追加
242ce59  chore(audit): 独立監査基盤を導入し、秘密とデプロイの穴を塞ぐ  ← 削除
```

`.env.local` へ書くつもりのリダイレクトが `.env.localecho` を作り、
当時の `.gitignore` が完全一致指定だったため素通りした（監査 D2-01 / `.audit/REMEDIATION.md`）。
`.gitignore` は現在 `.env.*` で無視するよう直っており、**同じ入り方は再発しない。**

**指紋照合の結果、履歴の鍵はいま使っている鍵と同一である。**

```
履歴の鍵の指紋 : b952cd9dfda8603b
現行の鍵の指紋 : b952cd9dfda8603b
```

## 到達性（2026-08-19 時点）

| ref | 鍵に到達するか |
|---|---|
| `origin/main` ほか origin の全ブランチ（非公開 NEO-AX/YDB） | **到達する** |
| ローカルの `main` および作業ブランチ | **到達する** |
| 公開リモート `mirror=ymatsushita-creator/YDB` | 到達しない（78コミット遅れていた） |

**公開はされていない。** ただし `git push mirror main` 一発で公開される状態だった。
そのため `mirror` remote を外した（復旧するなら
`git remote add mirror https://github.com/ymatsushita-creator/YDB.git`）。

## なぜ機械が黙っていたか

`kurosaki scan` も監査 D6-02 も**作業ツリーしか見ない。**
鍵は作業ツリーから消えているので「確定パターン11種では秘密を検出しなかった」と報告する。
緑は正しく、そして無意味だった。

構成基準に **S9** を足し、履歴に `.env` 系が追加されていないか、
origin 以外のリモートが増えていないかを `pnpm verify` で見るようにした。
**これはパスを見る検査であり、任意ファイルの中身までは見ていない。**

## やること（順番に意味がある）

### 1. 鍵を失効・再発行する ―― 最優先。人間が行う

<https://console.anthropic.com/> の API キー管理で、当該キーを **revoke** し、新しいキーを発行する。
`.env.local` を新しい値へ書き換える。**AIはこれを実行できない**
（`.claude/settings.json` が `Read(.env*)` を deny。鍵の入力自体も禁止）。

**これが唯一確実な対処である。** 履歴を書き換えても、
GitHub 上に存在した事実・クローン・フォーク・キャッシュは取り消せない。
失効させれば、履歴に残った文字列はただの無効な文字列になる。

### 2. 公開先を決める ―― 人間が行う

`mirror` は外してある。公開先が要るなら、push の前段に監査の合格を必須にしてから戻す。
不要なら GitHub 側のリポジトリ自体を畳む。**監査 D3-06 は10回連続で同じ指摘を出している。**

### 3. 履歴から除去する ―― 不可逆操作。人間の承認が要る

1 を済ませれば緊急ではない。行うなら `.audit/IRREVERSIBLE_OPS.md` の手順に従う。

```
git filter-repo --path .env.localecho --invert-paths
```

全コミットのハッシュが変わる。origin への force push と、
他の作業ブランチの取り直しが必要になる。**先に 1 を終えること。**

### 4. S9 を通す

1〜3 が済むまで `pnpm verify` は S9 で落ちる。**この検査を緩めて通さない**
（`CLAUDE.md`「検査を通すために検査の側を緩めること」の禁止）。
履歴の除去まで踏み込まないと決めた場合は、
`.audit/allowlist.yml` へ人間の承認と指紋つきで登録する ―― それが既存の正規経路である。
